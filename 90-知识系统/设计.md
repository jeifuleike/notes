# 知识系统设计

日常用法与双机安装见 [[使用说明]]。

## 目标

把日常对话、文章、代码经验和 Skill 变成可检索、可审计、可回滚的知识资产。系统只做四件事：收集、判断、融合、发布。

Markdown 是唯一存储，Git 是版本与回滚，Python 做确定性检查，Codex 做判断与写作，Skill 只负责调用。

## 四层

| 层 | 内容 | 目录 | 读者 |
|---|---|---|---|
| 人类知识 | 原理、教程、案例、复盘 | `10-前端/`、`20-后端/`、`30-AI与Agent/`、`40-读书笔记/`、`60-股市/` | 你 |
| AI 知识 | 工作流规范、工程约束、决策、项目上下文、来源笔记 | `70-AI知识资产/` | Codex |
| 收藏 Skill | 第三方或自己收集的 Skill 包与评估 | `80-Skill库/` | Codex |
| 系统机器 | 模板、脚本、配置、日志、知识库自身 Skill | `90-知识系统/` | 维护者 |

`50-每日自律/` 保持现有日期结构，不纳入知识沉淀编号。

## 知识库自身 Skill

只做三个，备份放在 `80-Skill库/Codex备份/skills/`：

- `kb-curator`：唯一有写权限。默认只写 `00-Inbox/` 和 `00-Inbox/审核/`。
- `kb-query`：严格只读检索，返回路径、行号和片段。
- `codex-asset-sync`：在本机和 `notes` 备份之间复制、比较、恢复 Codex Skill 与全局规则。

收藏的 Skill 放 `80-Skill库/候选|已采用|已淘汰/`；Codex 自定义 Skill 备份放 `80-Skill库/Codex备份/skills/`。两套索引分开：`80-Skill库/00-索引.md` 登记收藏 Skill，`Codex备份/manifest.json` 登记运行副本的哈希。

## 数据模型

Inbox 条目：

```yaml
---
type: inbox
status: new
captured: 2026-11-16T20:00
source:
kind: article
capture_reason: gotcha
value: unknown
tags: []
---
```

`capture_reason` 取值：`repeatable`、`decision`、`gotcha`、`source`、`workflow`、`manual`。

人读笔记只要求新笔记带最小 frontmatter，旧笔记不批量改写：

```yaml
---
title:
type: knowledge
domain:
topic:
status: active
created:
updated:
sources: []
tags: []
---
```

AI 操作卡：

```yaml
---
type: ai-card
status: active
scope:
audience: ai
reviewed:
sources: []
tags: []
---
```

正文固定包含：适用场景、输入与前置条件、必须遵守、禁止、检查清单、失败信号与处理、来源。每张卡不超过 100 行，必须反向链接人读笔记。

## 模板原则

- 收集类模板只保证条目能被检索和归档，不要求当场分类。
- 人读笔记用注释写引导问题，注释在阅读视图不渲染，不靠章节数量撑长度。
- AI 卡只写执行必需的信息，原理和例证留在人读笔记。
- 模板不放空话占位，宁可留白让作者填；填不出来的段落直接删。

工作流规范：

```yaml
---
type: ai-workflow
status: active
scope: global
audience: ai
version: 1
reviewed:
sources: []
---
```

## 分级

| 级别 | 内容 | 产出 |
|---|---|---|
| L1 | 一句话、链接、临时想法 | 合并进旧笔记，或淘汰 |
| L2 | 文章、教程、原理 | 人读笔记 + 来源 |
| L3 | 工程约束、踩坑、决策 | 人读笔记 + AI 操作卡 |
| L4 | 反复执行、输入输出稳定 | AI 操作卡 + Skill 候选 |

不是每篇都生成 AI 卡，也不是每篇都生成 Skill。

## 工作流

### 收集

用户说“记一下”“沉淀”“这个以后有用”，或 Codex 在最终回复中提议并得到确认后，写入 `00-Inbox/`。一条收集一个文件；Skill 包可以是一个文件夹。不写正式库，不询问是否发布。

### 整理

`kb-curator` 读取 Inbox，逐条检查：

1. 是否重复，优先合并。
2. 是否可靠、是否过时。
3. 属于 L1-L4 哪一级。
4. 目标路径和将改动的文件。
5. 风险与不确定。

第一步先运行 `kb.py review` 生成报告骨架：列出待处理条目、按标题相似度给出重复候选、追加处理日志。随后由 Codex 补齐价值分级、目标路径、动作和风险。默认只产出 `00-Inbox/审核/YYYY-MM-DD-HHmm-审核报告.md`，不改正式库。

### 审核

用户回复“执行 1、3”或“全部执行”。未列出的条目保持不动。

### 发布

创建或合并人读笔记；必要时生成 AI 操作卡；追加 `处理日志.md`；更新导航；把原始资料移到 `00-Inbox/已归档/YYYY-MM/`。

发布后展示 `git status` 和 `git diff --stat`，不自动提交。

### 审计

每月运行：

```powershell
python "D:\notes\90-知识系统\脚本\kb.py" doctor
python "D:\notes\90-知识系统\脚本\kb.py" lint
```

只报告，不自动修复。

## 权限

- `kb-curator` 是唯一有写权限的 Skill。
- 默认只写 `00-Inbox/` 和 `00-Inbox/审核/`。
- 正式发布必须得到用户明确确认；不逐条询问是否发布。
- 禁止覆盖同名笔记，冲突加 `-2`。
- 不修改 `.obsidian/workspace.json`。
- 不自动 `git commit`。
- 移动或重命名后检查双链、Markdown 链接和图片。

## 路由

`config.json` 是唯一路由来源。当前领域：

| 领域 | 目录 |
|---|---|
| 前端 | `10-前端` |
| 后端 | `20-后端` |
| AI 与 Agent | `30-AI与Agent` |
| 读书 | `40-读书笔记` |
| 每日自律 | `50-每日自律` |
| 股市 | `60-股市` |

新增领域时只改 `config.json` 和根 `AGENTS.md`。

## 索引与导航

`kb.py index` 生成根目录 `00-知识库首页.md`，把每个领域的导航页、主题目录和笔记用双链列出来。生成内容包在 `<!-- BEGIN kb-index -->` 标记内，重跑只替换这一段，标记外可以手写。超过 30 篇的目录只列子目录和篇数，避免日报这类高频目录淹没导航。

Obsidian 的反向链接面板会自动显示每篇笔记被谁引用，这就是 wiki 式的双向连接，不需要往每篇笔记里写返回首页的链接。

## 检索扩展

默认只用 `kb.py search` 的词法检索，不引入外部服务。需要语义检索时运行 `kb.py export` 导出 `90-知识系统/导出/qmd.jsonl`（已加入 `.gitignore`），交给 QMD 建索引；接入步骤见 `安装/qmd.md`。词法检索保留为兜底，QMD 不可用时不影响基本查询。

## 主动询问

两层：

1. 全局 `~/.codex/AGENTS.md` 写行为规则，Codex 在最终回复末尾自行判断。
2. `kb-curator` 的 `description` 写触发条件，用户明确说“记一下/沉淀”时执行。

不使用 Stop hook 强制追加一轮；用户确认后才由 `kb-curator` 写入 `00-Inbox/`。

### 提议门槛

四个问题至少两条为“是”才提议：离开当前项目还成立、三个月后还会用、能写成一句可执行规则、现有笔记未覆盖。

只提议两类：通用知识（原理、方法、模式、决策框架、边界）和提效资产（流程、脚本、模板、检查清单）。单次小修复、偶发环境问题、一次性命令不提议；踩坑能提炼成规则时，提议规则而不是事件。

### 提问格式

先写三行：要存什么（标题 + 最多 3 条要点）、为什么值得存（未来什么场景会用）、去向 `00-Inbox`，再问一句是否记录。不能只问“要沉淀吗”。

## 双机安装

源文件在 `90-知识系统/安装/`、`80-Skill库/Codex备份/skills/` 和 `90-知识系统/prompts/`，通过 `install-codex-kb.ps1` 复制到 `~/.codex/`。`~/.codex` 是运行目录，`notes` 只作备份；不使用 junction。每台机器只改自己的 `~/.codex/codex-assets.json` 的 `vault`；只有启用可选 Hook 时才改 `kb-capture.json` 的 `scope`：

- 家里：`vault = D:\notes`，`scope = all-projects`。
- 公司：`vault = 公司知识库`，`scope = vault-only`；没有公司知识库就关闭。

公司内容不得写入个人知识库。

## Codex 资产同步

`codex-asset-sync` 只在本机运行，读取 `~/.codex` 和 `notes` 备份，先比较 SHA256 和文件差异，再由 AI 给出备份或恢复方案。备份目录为 `80-Skill库/Codex备份/skills/`、`90-知识系统/prompts/AGENTS.global.md`；同步清单和哈希在 `80-Skill库/Codex备份/manifest.json`。

同步范围仅限清单内 Skill 和 `AGENTS.md` 的 `codex-kb` 标记块，不同步认证、模型、插件、日志和其他机器配置。

## 验收

- “记一下”一分钟内生成 Inbox 条目。
- “整理临时区”只产出报告，正式笔记零改动。
- 批准后只改报告列出的文件。
- 发布后无新增断链，`doctor` 通过。
- AI 卡不超过 100 行，且能反向链接人读笔记。
- 不使用 Stop hook 时，Codex 仍在最终回复中按门槛自然提议，不额外追加一轮。
- `~/.codex/skills` 是真实副本，不依赖 `notes` junction。
- `python -m unittest discover -s 90-知识系统/脚本/tests` 全部通过。

## 非目标

- 不建 Web 平台。
- 不提前上向量数据库。
- 不把所有笔记塞进 `AGENTS.md`。
- 不把每条知识都包装成 Skill。
- 不让后台 Agent 无人值守修改正式库。
