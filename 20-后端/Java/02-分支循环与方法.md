# 第 02 节　还有几名成员有待办？

上一节算出一个人的剩余数。如果三个人分别剩下 `3、0、2` 项，现在问的是**有待办的人数**，不是待办总数。先手算：答案是 2，不是 5。

## 先认清四个问题，不把四种写法一起背

| 遇到的问题 | 用什么解决 | 它不负责什么 |
| --- | --- | --- |
| 怎样决定这个人算不算？ | 条件产生真假，`if` 决定是否执行一段代码 | 不负责换到下一个人 |
| 三个人的数量放在哪？ | `int[]` 把同类型的多个值按顺序放进数组 | 数组自己不会统计 |
| 怎样对每个人做同一件事？ | 循环重复执行一段代码，每轮处理一个元素 | 循环不会自动记住答案，要自己维护计数 |
| 换一组人还要抄一遍吗？ | 方法给这段计算起名，用参数换输入，用返回值交出答案 | 返回不是打印；调用者决定是否显示 |

## 1　先判断一个人，不要急着写循环

在练习目录新建完整文件 `PendingCount.java`，用 JDK 21 在同一目录执行 `java PendingCount.java`。下面先只问一件事：这个人是否还有待办？

```java
class PendingCount {
    public static void main(String[] args) {
        int remaining = 3;
        boolean hasPending = remaining > 0;
        System.out.println(hasPending);
    }
}
```

第一行保存数量，第二行比较数量与零，把结果 `true` 存进布尔变量。把 `3` 改成 `0`，输出就变成 `false`。`>` 不包含相等；`>=` 包含。= 是存入值，比较两个整数是否相等用 == ，不相等用 `!=`。两个条件都要满足用 `&&`，任一个满足用 `||`，取反用 `!`。这里输入约定为非负整数，只需一个比较。

现在只把打印那行替换为下面这个分支。以 `3` 和 `0` 分别运行，预期是「有待办」和「已清空」：

```java
if (hasPending) {
    System.out.println("有待办");
} else {
    System.out.println("已清空");
}
```

`if` 的括号必须是真假值；Java 不把整数 `3` 当成真。花括号里的代码只在对应分支执行。只需处理满足条件的人时，可以省略 `else`；要在多个条件中选第一项，可接 `else if`；若根据几个明确的值选不同路径，可用 `switch`。这次统计中，遇到 0 只需不计数，不用特意写一个空分支。

## 2　先把一组数读出来，再谈统计

保留类和 `main` 的外壳，把 `main` 内的内容全部换成下面三行：

```java
int[] remaining = {3, 0, 2};
System.out.println(remaining.length);
System.out.println(remaining[1]);
```

预期先打印 `3`（有三个元素），再打印 `0`（第二个人的数量）。方括号里的**下标从 0 开始**：下标 0、1、2 对应值 3、0、2。数组创建后长度不变。把 `[1]` 换成 `[3]`，程序会在取值处报 `ArrayIndexOutOfBoundsException`：长度是 3，但没有下标 3。改回 `[1]` 恢复。

逐个写 `remaining[0]`、`remaining[1]` 的坏处是人数一变就得改代码。保留数组声明，把两行打印替换成以下循环：

```java
for (int amount : remaining) {
    System.out.println(amount);
}
```

冒号读作“依次从右边取一个，放进左边的变量”。预期三行分别是 `3`、`0`、`2`。这种增强 `for` 适合只关心每个值的场合；需要位置时用普通 `for`，例如 `for (int index = 0; index < remaining.length; index++)`：先把位置设为 0，每轮先检查有没有越界，执行后再加 1。若不知道要重复几轮，只知道继续的条件，用 `while`；`do … while` 把检查放在末尾，至少执行一次。空数组应处理零个人，所以这里不选后者。

## 3　把“打印每个值”换成“累计符合条件的人数”

仍保留数组声明，用下面的内容替换整个循环。先手推一遍再运行：

```java
int count = 0;
for (int amount : remaining) {
    if (amount > 0) {
        count = count + 1;
    }
}
System.out.println(count);
```

| 本轮取到的值 | `amount > 0` | 本轮前 → 本轮后 |
| --- | --- | --- |
| 3 | 真 | 0 → 1 |
| 0 | 假，跳过加法 | 1 → 1 |
| 2 | 真 | 1 → 2 |

`count` 在循环外只初始化一次。每轮加的是 **1 个人**，不是 `amount` 项任务。把 `+ 1` 换成 `+ amount`，程序完全可以运行，却回答了另一个问题（总计 5 项）。改回 `+ 1`。

## 4　把已经会做的计算变成可重复调用的方法

现在需求是对两个团队做同样的统计。与其复制循环，不如只把组内数据作为输入。方法头 `static int countPending(int[] amounts)` 从中间读：名字是 `countPending`，圆括号声明“调用时要给我一组整数”，名字前的 `int` 承诺交回一个整数。`static` 在这里允许 `main` 不创建对象就调用它。参数 `amounts` 和调用处的变量可以不同名。

下面是最终的**完整文件**。注意方法与 `main` 并列，都在类里面；不要把方法声明塞进 `main`：

```java
class PendingCount {
    public static void main(String[] args) {
        int[] remaining = {3, 0, 2};
        System.out.println(countPending(remaining));
    }

    static int countPending(int[] amounts) {
        int count = 0;
        for (int amount : amounts) {
            if (amount > 0) {
                count = count + 1;
            }
        }
        return count;
    }
}
```

运行 `java PendingCount.java`，预期输出 `2`。顺着执行顺序读：

1. `main` 创建整数数组。`int[]` 表示里面每个元素都是整数；`countPending(remaining)` 把整组数传给方法，方法里用参数名 `amounts` 指代它。
2. `for (int amount : amounts)` 类似 TS 的 `for … of`：每次取一个数。`if` 只在括号里的判断为真时执行。依次读到 3、0、2 时，`count` 依次变成 1、1、2。
3. `return count` 把答案交还给调用处，最后才由 `println` 输出。方法名前的 `int` 是返回值类型；`static` 让 `main` 不必先创建对象就能调用它。

**试错：**把 `> 0` 改成 `>= 0`，先预测，再运行。预期程序照常执行却输出 3：没任务的人也被计入。改回 `> 0`。这次不是语法错，而是判断条件写错了。

## 关掉示例，自己验收

先把同一个方法分别用于空数组、两个零、两个一，预期返回 0、0、2。提示：在调用处直接构造数组可以写 `countPending(new int[]{0, 0})`。空数组不需要特殊分支：循环体执行零次，`return` 仍交回初始计数。

再独立写 `countAtLeast`：除了数组，还接受一个门槛，只统计数量**达到或超过**门槛的人。用 `{3, 0, 2}` 和门槛 2、3、4 分别测试，答案应是 2、1、0。若第二组错了，先看相等时应不应该计入；若第二次调用还带着第一次的结果，检查计数器是不是在每次方法调用时才初始化。下一节不再只问“有几人”，而要回答 [[20-后端/Java/03-类对象与列表|这些人是谁]]。
