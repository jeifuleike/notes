# 使用说明

## 日常四句话

| 你说 | 发生什么 |
|---|---|
| 记一下 / 沉淀 / 这个以后有用 | 写一条到 `00-Inbox/`，不写正式库，不问发布 |
| 整理临时区 | 只生成 `00-Inbox/审核/时间-审核报告.md`，正式笔记不动 |
| 执行 1、3 / 全部执行 | 只改报告里列出的文件 |
| 找一下以前关于 X 的笔记 | `kb-query` 只读检索，返回 `路径:行号` |
| 备份 / 恢复 / 检查 Codex 资产 | `codex-asset-sync` 比较本机与 notes 备份，确认后复制 |

## Obsidian 一键收集

QuickAdd 里已经加好 `收集到 Inbox`：命令面板运行它，或点左侧 QuickAdd 图标，输入标题和一句话内容，会在 `00-Inbox/` 生成带 frontmatter 的条目，文件名格式 `日期-时间-标题.md`。

改完配置后需要重启 Obsidian 或重载 QuickAdd 才会出现；没有的话在 QuickAdd 设置里删掉重建，模板选 `90-知识系统/模板/QuickAdd收集.md`，目标文件夹 `00-Inbox`。

Templater 的模板目录指向 `90-知识系统/模板/`，工作日、休息日模板和知识库模板都在这里，插入模板时列表只显示这 9 个。QuickAdd 的收集选项也指向这个目录。

## 主动询问

不再用 Stop hook 强制追加一轮。Codex 在最终回复末尾按 `~/.codex/AGENTS.md` 的规则自行判断：只有通用知识或提效资产才提议，单次小修复和偶发环境问题跳过。提议会先说明要存什么、为什么值得存、去向 `00-Inbox`，再问是否记录。

## Codex 资产备份

Codex 实际读取 `~/.codex/skills/` 和 `~/.codex/AGENTS.md`。`notes` 只保存可版本管理的备份，不使用 junction：

- Skill 备份：`80-Skill库/Codex备份/skills/`
- 全局提示词备份：`90-知识系统/prompts/AGENTS.global.md`
- 同步状态：`80-Skill库/Codex备份/manifest.json`

以后直接说“备份 Codex 资产”“检查本机和 notes 的 Skill 差异”“从 notes 恢复 Skill”。AI 会调用 `codex-asset-sync`：先只读比较，给出方案；你确认后才复制。恢复前会保留本机旧版本，不覆盖清单外的 Skill。

## 装到另一台机器

把 `D:\notes` 整个仓库同步过去，然后在该机器执行：

```powershell
& '<知识库路径>\90-知识系统\安装\install-codex-kb.ps1' -VaultPath '<知识库路径>' -Scope all-projects
```

公司机器：

```powershell
& '<知识库路径>\90-知识系统\安装\install-codex-kb.ps1' -VaultPath '<公司知识库路径>' -Scope vault-only
```

- `-Scope vault-only`：只在公司知识库目录内触发，避免公司内容流进个人库。
- 安装器默认把 Skill 复制到 `~/.codex/skills/`，不创建 junction，也不安装 Stop hook。
- 需要试验 Hook 时才加 `-EnableCaptureHook`，然后按 Codex 提示审核；日常不需要。

## 排错

```powershell
python "<知识库路径>\90-知识系统\脚本\kb.py" doctor
```

- Skill 没生效：确认 `~/.codex/skills/<名称>/SKILL.md` 是本机真实目录，不是指向 notes 的 junction。
- 提示词不一致：对 Codex 说“检查 Codex 资产差异”，让 `codex-asset-sync` 先比较再处理。

## 月度审计

```powershell
python "D:\notes\90-知识系统\脚本\kb.py" audit
```

报告写到 `90-知识系统/审计/YYYY-MM.md`：笔记数、待处理条目、审核报告、AI 卡、断链和重复标题。有错误时命令返回非零，适合挂到定时任务或 Codex 自动化。每月一次即可，审计只报告不改文件。

## 定时任务

Codex 自动化里只保留一个任务：

- 每月 1 日 09:00 `每月知识库审计`：跑 `audit`，读当期审计报告，给前三条建议，不改文件。

任务只读或只生成报告，不会自动发布、不会 `git commit`。需要时手动说“整理临时区”。要暂停或改时间，在 Codex 的自动化面板里操作。

## 自动日报

```powershell
python "D:\notes\90-知识系统\脚本\kb.py" daily
python "D:\notes\90-知识系统\脚本\kb.py" daily --date 2026-11-21
python "D:\notes\90-知识系统\脚本\kb.py" daily --dry-run
```

按日期自动选模板：周一到周五用工作日模板，周六周日用休息日模板；文件写到 `50-每日自律/日报/YYYY-MM/YYYY-MM-DD.md`，已存在且非空时不动。

法定假日和调休改 `90-知识系统/config.json` 的 `daily.rest_days` 和 `daily.work_days`，日期写 `YYYY-MM-DD`；2026 年安排已配置，后续年份需按当年官方通知补充。`work_days` 优先级最高，其次是 `rest_days`，最后才按周末判断。

本机已挂两个触发：Windows 计划任务 `Codex-KB-DailyNote` 每天 06:00 运行，启动文件夹快捷方式在登录时补跑一次。日志在 `~/.codex/kb-daily.log`。不想要自动创建，删掉这个计划任务和启动快捷方式即可。

## 工具命令

```powershell
$kb = "D:\notes\90-知识系统\脚本\kb.py"
python $kb review              # 生成审核报告骨架
python $kb review --dry-run    # 只看不写
python $kb inbox               # 列出待处理条目
python $kb search "关键词"      # 词法检索
python $kb lint                # 断链、重复标题、过期卡片
python $kb index               # 重建 00-知识库首页.md
python $kb audit               # 月度审计报告
python $kb export              # 导出 QMD 用的 JSONL
python -m unittest discover -s "D:\notes\90-知识系统\脚本\tests"
```
