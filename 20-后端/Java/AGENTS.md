# Java 后端课程编写要求

本目录的读者有 Vue、TypeScript、Express、Nest 和 MySQL 实践经验，正在把 Java 作为主力后端语言。选题、每节的类比起点和验收任务见 [[20-后端/Java/00-Java后端学习路线]]。从读者以前写过的一行代码、遇到过的故障或熟悉的需求讲起。

## 一节课怎样展开

1. **给一个实际问题。** 开头点明读完可以做什么。沿用团队任务项目中的用户、项目、成员、任务和变更记录。新需求尽量建立在上节可运行的结果上。
2. **选一个准确的类比。** 指出旧知识能解释的部分，再说清一个会误导判断的差异。例如用 Nest 的构造函数注入理解 Spring Bean，用 mysql2 的同一条连接理解事务，用浏览器 Network 定位请求超时。读者已经做过的 SQL、JWT 和 CRUD 直接链接原笔记，把篇幅给 Java 新机制。
3. **走读一段关键代码。** 先让读者看到输入、调用者和预期输出，再顺着一条调用路径解释“谁创建、谁调用、什么时候失败”。首次出现的 Java 语法用一句人话解释用途，较深入的细节放到路线对应的课次。
4. **交付最小可运行示例。** 标清 JDK 或依赖前提、文件名、包和执行目录。命令适用于 Windows PowerShell。给出关键输出、HTTP 状态或数据库结果。知识正文维护在笔记库；已有独立工程时，链接源文件和测试，完整运行手册留在工程里。
5. **安排一次可观察的失败。** 写清“先预测什么、改变哪一个条件、从哪里看结果、怎样恢复”。按当节主题选失败点，例如编译期类型错误、事务回滚或外部服务超时。测试过的代码可以报告实际结果；未执行的步骤标为预期。
6. **留一个独立改动。** 给输入、约束和可检查的结果，留出自己选择实现的空间。末尾给出能进入下一节的判断标准。写出了教材与读者完成练习分别记录。

## 控制深度

- 语法课讲到能运行、能读懂错误。框架课讲清对象和调用边界。并发与事务课检查最终状态，观测与排障课拿日志、指标、执行计划或线程快照支持判断。
- 每节集中解决一个主问题。已有基础用最短的对照带过；遇到跨语言差异、故障或容易写出错误代码的地方可以放慢。预计普通课 60～90 分钟，允许实验拆成两次。
- 单测、真实数据库测试和本地实验各写明能证明什么。业务涉及并发、重试或权限时，验收需覆盖相应的失败路径。

## 示范：第 16 节怎样写

从“Express Service 把同一条连接传给两个 Repository”讲起。让读者预测“Spring 里两个 Mapper 都没接收连接参数，第二次写失败后，第一条记录会怎样”。展示一个 Service 和两次写入，说明代理调用与事务管理的关系，在独立连接中查表。最后调整调用位置，让读者用前后结果解释事务边界。
