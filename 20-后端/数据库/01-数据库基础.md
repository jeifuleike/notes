# 数据库基础

本篇只建立数据库基本概念。表设计、键、索引等分别在后续文档展开。

## 1. 数据库是什么

数据库（Database）是用于：

-   存储数据
-   管理数据
-   查询数据
-   修改数据

的软件系统。

简单理解：

    应用程序
        |
        ↓
    数据库
        |
        ↓
    保存的数据

例如：

用户注册：

    用户输入账号密码

            ↓

    后端服务

            ↓

    MySQL保存用户数据

------------------------------------------------------------------------

## 2. 关系型数据库

MySQL 属于：

> 关系型数据库（Relational Database）

核心思想：

使用：

    表（Table）

保存数据。

例如：

用户表：

  id   username   email
  ---- ---------- -------------
  1    Tom        tom@qq.com
  2    Jack       jack@qq.com

这里：

-   一张表代表一种数据
-   一行代表一条记录
-   一列代表一个属性

------------------------------------------------------------------------

## 3. 数据库中的基本概念

### 1. Database

数据库。

例如：

    project_system

一个数据库可以包含很多表。

------------------------------------------------------------------------

### 2. Table

表。

例如：

    users

    projects

    tasks

------------------------------------------------------------------------

### 3. Row

行，也叫记录。

例如：

    id=1
    username=Tom
    email=tom@qq.com

代表一个用户。

------------------------------------------------------------------------

### 4. Column

列，也叫字段。

例如：

    username
    email
    created_at

表示数据属性。

------------------------------------------------------------------------

## 4. 数据类型

常见类型：

### 整数

``` sql
INT
BIGINT
```

例如：

    用户ID
    订单ID
    数量

### 字符串

``` sql
VARCHAR
TEXT
```

例如：

    用户名
    标题
    描述

### 时间

``` sql
DATETIME
TIMESTAMP
```

例如：

    创建时间
    更新时间

### 布尔状态

通常使用：

``` sql
TINYINT
```

例如：

    status

    1 启用
    0 禁用

------------------------------------------------------------------------

## 5. NULL是什么

NULL 表示：

> 没有值。

例如：

用户没有填写手机号：

    phone=NULL

注意：

NULL 不等于：

    0

    空字符串 ''

它代表未知或不存在。

------------------------------------------------------------------------

## 6. 数据库查询流程基础理解

简单查询：

``` sql
SELECT *
FROM users
WHERE id=1;
```

数据库大概流程：

    接收SQL

    ↓

    解析SQL

    ↓

    选择执行方式

    ↓

    访问数据

    ↓

    返回结果

后面学习索引后，会进一步理解：

    查询
     ↓
    索引
     ↓
    B+ Tree
     ↓
    定位数据

------------------------------------------------------------------------

## 7. 数据量增长后的问题

小项目：

    一张表
    几千数据

简单即可。

数据增加：

    百万
    千万
    亿级

需要考虑：

-   索引
-   SQL优化
-   缓存
-   分库分表
-   数据一致性
