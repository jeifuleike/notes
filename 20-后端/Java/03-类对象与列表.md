# 第 03 节　从成员对象到 Java 面向对象基础

上一节已经能用数组、循环和方法统计“有多少人有待办”。但业务接下来会问：**具体是谁有待办？每个人除了姓名，还有哪些数据和行为？** 如果继续用多个数组分别保存姓名、数量和状态，很容易在排序、增删时把不同人的数据错配。

这一节把数据放进对象，并继续学习 Java 面向对象的核心机制：构造方法、`this`、`static`、`final`、封装、继承、抽象类、接口和多态。最后再用 `List<Member>` 管理多名成员。

学完本节，你应该能够：

- 解释类、对象、引用变量之间的关系；
- 看懂 `new Member(...)`，知道构造方法何时执行；
- 区分实例成员、静态成员和局部变量；
- 使用 `private`、Getter、Setter 实现基本封装；
- 看懂 `extends`、`implements`、抽象类、接口和多态；
- 使用 `List<Member>` 保存、遍历和管理成员对象。

## 准备环境

本节示例以 **JDK 21** 为准。先找一个空目录，在该目录打开 Windows PowerShell。示例默认不声明 `package`，这样可以先专注理解类和对象；包名、源码目录和类路径会在 [[20-后端/Java/04-从TypeScript到Java-编译与运行|第 04 节]] 详细学习。

本节会出现多个独立的小示例。每个标注为“完整文件”的代码块都可以单独保存运行；其他代码块是局部示例，按上下文阅读即可，不要把多个同名类同时复制进一个文件。

## 1　类、对象与引用变量：定义和具体成员不是一回事

### 1.1 先看一个成员对象

在练习目录新建 `MemberDemo.java`，写入下面的完整代码：

```java
class MemberDemo {
    String name;
    int remaining;

    public static void main(String[] args) {
        MemberDemo first = new MemberDemo();
        first.name = "小林";
        first.remaining = 3;

        System.out.println(first.name);
        System.out.println(first.remaining);
    }
}
```

在 PowerShell 中执行：

```powershell
java MemberDemo.java
```

预期输出：

```text
小林
3
```

这里有两个层次：

- `class MemberDemo { ... }` 定义了一个**类**。类描述一类对象有哪些数据、能做什么事情。
- `new MemberDemo()` 创建了一个具体的**对象**。对象是类的一个实例（instance）。

可以把类暂时理解为设计图，把对象理解为按照设计图创建出来的具体东西。设计图不是某一件具体物品；同样，类也不等于某个对象。

### 1.2 拆开 `MemberDemo first = new MemberDemo()`

这行代码可以分成三部分：

```java
MemberDemo first = new MemberDemo();
```

| 片段 | 含义 |
| --- | --- |
| `MemberDemo` | 变量声明类型：它能引用 `MemberDemo` 类型的对象 |
| `first` | 变量名 |
| `new MemberDemo()` | 创建一个 `MemberDemo` 对象，并得到指向该对象的引用 |

因此，`MemberDemo first` 是声明一个变量，`new MemberDemo()` 才是创建对象。两者不是同一件事。

Java 的类可以作为变量类型，因为类定义了一种引用类型。你可以像声明 `int`、`String` 一样声明自己定义的类类型：

```java
int count = 3;
String name = "小林";
MemberDemo member = new MemberDemo();
```

`int` 是基本类型；`String` 和 `MemberDemo` 是引用类型。引用变量保存的是对象引用，不是把整个对象直接装进变量。

### 1.3 两个变量，是两个对象还是同一个对象？

看下面两种写法：

```java
MemberDemo first = new MemberDemo();
MemberDemo second = new MemberDemo();
```

这里执行了两次 `new`，所以创建了两个独立对象。修改 `first.name` 不会自动修改 `second.name`。

再看另一种写法：

```java
MemberDemo first = new MemberDemo();
MemberDemo second = first;

second.name = "小周";
System.out.println(first.name);
```

输出是：

```text
小周
```

为什么？第二行没有执行 `new`，没有创建第二个对象，而是把 `first` 保存的引用复制给 `second`。现在两个变量指向同一个对象。通过任何一个变量修改对象，都能从另一个变量看到变化。

可以用下面的图理解：

**执行两次 `new`：两个独立对象**

```text
first  ──引用──> 对象 A（name = 小林）
second ──引用──> 对象 B（name = 小周）
```

**执行 `second = first`：两个变量指向同一对象**

```text
first  ──┐
         ├──引用──> 对象 A（name = 小周）
second ──┘
```

这也是为什么“变量赋值”要看类型：基本类型赋值复制的是数值；引用类型变量赋值复制的是引用。它们的结果不同。

### 1.4 为什么 `String first = new MemberDemo()` 不行？

```java
String first = new MemberDemo(); // 编译错误
```

左边要求一个 `String` 对象，右边创建的是 `MemberDemo` 对象，两种类型没有可用的赋值兼容关系，所以编译器拒绝。

但下面是允许的：

```java
Object first = new MemberDemo();
```

因为 Java 中普通类最终都继承自 `Object`。子类对象可以由父类类型的变量引用。这里先知道“类型之间必须兼容”即可，继承和向上转型会在本节后面展开。

### 1.5 `null`、字段默认值和局部变量初始化

引用变量可以暂时不指向任何对象：

```java
MemberDemo member = null;
```

`null` 表示当前没有对象引用。它不等于空字符串 `""`，也不等于内容为 `"null"` 的文本。

如果对 `null` 直接访问成员：

```java
member.name = "小林";
```

运行时会抛出 `NullPointerException`，因为没有实际对象可供访问。

还要区分**成员字段**和**局部变量**：

| 声明位置 | 示例 | 未手动赋值时 |
| --- | --- | --- |
| 类中、方法外，不带 `static` | `String name;` | 对象创建后有默认值 |
| 方法中 | `int count;` | 没有默认值，必须先明确赋值才能读取 |
| 方法参数 | `void report(int count)` | 调用方法时由实参提供值 |

常见字段默认值：

| 字段类型 | 默认值 |
| --- | --- |
| `byte`、`short`、`int`、`long` | `0` |
| `float`、`double` | `0.0` |
| `char` | `\u0000`（空字符） |
| `boolean` | `false` |
| 引用类型，例如 `String`、`MemberDemo` | `null` |

局部变量没有这种自动默认值。下面会编译失败：

```java
int remaining;
System.out.println(remaining); // 可能尚未赋值
```

**本节先记住：**类是定义，对象是实例，引用变量用来找到对象；`new` 创建对象，单纯声明变量或复制引用不一定创建新对象。

## 2　构造方法：对象创建时怎样完成初始化

### 2.1 为什么需要构造方法？

上一节的对象需要先创建、再逐个设置字段：

```java
MemberDemo member = new MemberDemo();
member.name = "小林";
member.remaining = 3;
```

这种写法有一个风险：创建对象后，调用者可能忘记设置某个字段。构造方法可以把“创建对象时必须提供的数据”放在一起处理。

```java
class Member {
    String name;
    int remaining;

    Member(String name, int remaining) {
        this.name = name;
        this.remaining = remaining;
    }
}
```

创建对象时传入数据：

```java
Member member = new Member("小林", 3);
```

构造方法会在创建对象的过程中执行，把传入的姓名和待办数保存到这个新对象中。

### 2.2 构造方法的固定命名规则

构造方法有明确的语法规则：

1. 名称必须与类名**完全一致**，包括大小写。
2. 构造方法**没有返回值类型**，连 `void` 也不能写。
3. 构造方法可以有参数，也可以没有参数。
4. 一个类可以定义多个参数列表不同的构造方法，这叫构造方法重载。

例如类名是 `Member`：

```java
class Member {
    Member() { }                            // 构造方法
    Member(String name) { }                 // 另一个构造方法
    Member(String name, int remaining) { }  // 又一个构造方法
}
```

下面两种写法都不是 `Member` 的构造方法：

```java
class Member {
    void Member() { } // 普通方法，因为写了 void
    void member() { } // 普通方法，名称大小写不同
}
```

为什么 `void Member()` 不是构造方法？因为 Java 根据“方法名是否等于类名、是否声明返回类型”区分构造方法和普通方法。构造方法不声明返回类型。

### 2.3 构造方法重载

可以根据创建对象时掌握的信息，提供不同构造方式：

```java
class Member {
    String name;
    int remaining;

    Member() {
        name = "未命名";
        remaining = 0;
    }

    Member(String name) {
        this.name = name;
        remaining = 0;
    }

    Member(String name, int remaining) {
        this.name = name;
        this.remaining = remaining;
    }
}
```

调用时，Java 根据参数数量和类型选择匹配的构造方法：

```java
Member first = new Member();
Member second = new Member("小林");
Member third = new Member("小周", 3);
```

这和普通方法重载的基本规则相同：方法名相同，但参数列表不同。只改变返回值类型不能构成重载。

### 2.4 默认无参构造方法：什么时候自动提供？

如果一个类**完全没有声明任何构造方法**，Java 编译器会提供一个默认的无参构造方法。因此下面可以创建对象：

```java
class Member {
    String name;
}

Member member = new Member();
```

但是，只要你自己声明了任意一个构造方法，编译器就不会再自动提供无参构造方法：

```java
class Member {
    Member(String name) {
        this.name = name;
    }

    String name;
}

Member member = new Member(); // 编译错误：没有无参构造方法
```

如果业务仍然需要无参创建，就要自己显式写 `Member() { ... }`。

### 2.5 `new` 和构造方法分别做什么？

看这行：

```java
Member member = new Member("小林", 3);
```

可以先用这个简化顺序理解（暂时不展开父类构造方法、字段初始化表达式和实例初始化块）：

1. `new` 请求创建一个新的 `Member` 对象；
2. 对象的字段先获得默认值；
3. Java 执行对象初始化过程，并调用匹配的 `Member(String, int)` 构造方法；
4. 构造方法执行初始化代码；
5. 创建完成后，得到对象引用并赋给变量 `member`。

所以构造方法不是普通的“创建命令”，它负责对象创建过程中的初始化；`new` 才是创建对象的表达式。

### 2.6 `this`：当前正在初始化或使用的对象

构造方法中经常出现：

```java
Member(String name, int remaining) {
    this.name = name;
    this.remaining = remaining;
}
```

这里 `this` 表示当前对象本身：

- `this.name`：当前对象的成员字段 `name`；
- `name`：传入构造方法的参数。

两者同名时，`this.name` 用来明确指向字段。若参数和字段名称不同，也可以不写 `this`，但写出来通常更容易读懂。

`this` 不只用于构造方法，在实例方法中也表示当前对象。后面会继续看到。

### 2.7 构造方法与 `main` 不是一回事

| 对比 | 构造方法 | `main` 方法 |
| --- | --- | --- |
| 名称 | 必须与类名相同 | 入口方法名为 `main` |
| 返回值类型 | 不写返回类型 | 标准入口返回 `void` |
| 何时执行 | 创建对象时调用 | JVM 启动指定类时调用 |
| 主要职责 | 初始化对象 | 作为程序入口，开始执行代码 |
| 能否重载 | 可以 | 可以定义其他参数形式，但标准启动器识别标准入口形式 |

一个类可以同时拥有构造方法和 `main` 方法。下面把两者放在同一个类里：

```java
class Member {
    String name;

    Member(String name) {
        this.name = name;
        System.out.println("构造方法执行");
    }

    public static void main(String[] args) {
        System.out.println("main 开始");
        Member member = new Member("小林");
        System.out.println(member.name);
    }
}
```

运行 `java Member.java`，预期输出：

```text
main 开始
构造方法执行
小林
```

顺序是：启动器先调用 `main`；`main` 执行到 `new Member("小林")` 时，才调用构造方法；构造方法完成初始化后，`main` 继续执行。**启动哪个类，决定哪个类的 `main` 作为入口；创建哪个类的对象，决定调用哪个构造方法。**

**本节先记住：**构造方法与类同名、没有返回类型；没有声明任何构造方法时才会自动得到默认无参构造方法；`new` 创建对象，构造方法负责初始化。

## 3　实例方法与 `main`：谁调用方法，方法就为谁工作

### 3.1 实例方法需要一个具体对象

给 `Member` 增加一个方法：

```java
class Member {
    String name;
    int remaining;

    void report() {
        System.out.println(name + " 还有 " + remaining + " 项待办");
    }
}
```

调用时需要通过对象：

```java
Member first = new Member();
first.name = "小林";
first.remaining = 3;
first.report();
```

`first.report()` 的意思是：让 `first` 指向的这个对象执行 `report()`。方法内部直接写 `name` 和 `remaining`，访问的就是当前对象的字段。

这种不带 `static` 的方法称为**实例方法**。调用实例方法时，需要有一个具体对象作为调用者。

### 3.2 `this` 在实例方法里表示谁？

```java
void report() {
    System.out.println(this.name + " 还有 " + this.remaining + " 项待办");
}
```

如果执行 `first.report()`，那么方法里的 `this` 就是 `first` 当前指向的对象；如果执行 `second.report()`，`this` 就是 `second` 指向的对象。

因此，同一份方法代码可以服务于不同对象。方法代码定义在类里，但每次调用时操作的是指定的那个对象。

### 3.3 `main` 是什么？为什么通常写成 `public static void main(String[] args)`？

Java 启动器需要一个约定的入口方法。最常见的标准形式是：

```java
public static void main(String[] args) {
    // 程序从这里开始执行
}
```

逐个看：

| 片段 | 含义 |
| --- | --- |
| `public` | 入口方法对启动器公开 |
| `static` | 不需要先创建这个类的对象，就能通过类调用 |
| `void` | 方法不返回结果 |
| `main` | 标准入口方法名 |
| `String[] args` | 接收命令行传入的字符串参数 |

`main` 不是构造方法，也不是 Java 关键字；它是一个具有特殊入口约定的静态方法。

### 3.4 什么时候会自动执行 `main`？

更准确地说：**当你把某个类指定为 Java 程序的启动类时，启动器才会寻找并调用该类的入口方法。** 例如：

```powershell
java MemberDemo.java
```

这是 JDK 21 支持的源码启动方式。也可以先编译，再运行类：

```powershell
javac MemberDemo.java
java MemberDemo
```

如果另一个类里写着：

```java
Member member = new Member();
```

它只会创建对象并调用构造方法，不会自动执行 `Member` 类里的 `main`。

当然，其他代码可以主动调用一个可访问的静态方法，例如 `SomeClass.main(args)`；那是普通的方法调用，不是 JVM 把它当成程序入口自动启动。

**本节先记住：**实例方法由对象调用，`this` 指向当前调用者；`main` 是启动指定类时使用的入口，不会因为创建对象就自动执行。

## 4　`static`：属于类的成员与属于对象的成员

### 4.1 实例字段和静态字段的区别

团队成员有自己的姓名和待办数，但团队名称可能是大家共享的。可以这样表示：

```java
class Member {
    String name;                   // 实例字段
    int remaining;                 // 实例字段
    static String team = "后端组"; // 静态字段
}
```

- `name`、`remaining` 没有 `static`，每个对象各有一份。
- `team` 带有 `static`，属于 `Member` 这个类，所有 `Member` 对象共享同一份。

```java
Member first = new Member();
Member second = new Member();

first.name = "小林";
second.name = "小周";
Member.team = "平台组";
```

现在两个对象的姓名不同，但它们访问到的 `team` 都是 `平台组`。

**实例字段：每个对象一份**

```text
first 对象：  name = 小林，remaining = ...
second 对象： name = 小周，remaining = ...
```

**静态字段：整个类共享一份**

```text
Member.team = 平台组
```

推荐通过类名访问静态成员：

```java
Member.team = "平台组";
```

虽然 Java 允许通过对象变量访问静态成员，例如 `first.team`，但这种写法容易让人误以为每个对象各有一份，不推荐这样表达。

### 4.2 静态方法

静态方法也属于类，可以直接通过类名调用：

```java
class Member {
    static void printRule() {
        System.out.println("每名成员独立统计待办");
    }
}

Member.printRule();
```

实例方法与静态方法对比：

| 对比 | 实例方法 | 静态方法 |
| --- | --- | --- |
| 声明 | `void report()` | `static void printRule()` |
| 归属 | 具体对象 | 类 |
| 常见调用 | `first.report()` | `Member.printRule()` |
| 是否有当前对象 `this` | 有 | 没有 |
| 能否直接访问实例字段 | 可以 | 不可以，必须先明确某个对象 |

为什么静态方法不能直接使用 `name`？因为调用 `Member.printRule()` 时，可能一个 `Member` 对象都没有创建。此时并不存在唯一的“当前对象”，所以静态方法没有 `this`。

如果静态方法确实要访问对象数据，可以通过参数接收对象：

```java
static void printName(Member member) {
    System.out.println(member.name);
}
```

这不是静态方法直接访问实例字段，而是通过传入的 `member` 明确指定了对象。

### 4.3 为什么 `main` 是 `static`？

启动器开始执行程序时，还没有理由先创建某个业务对象。把入口声明为 `static`，就能通过类直接调用它，不需要先 `new` 一个对象。

### 4.4 `static` 适合什么，不适合什么？

适合放在类层面共享或不依赖具体对象的数据、工具方法，例如：

- 全体对象共用的常量；
- 不依赖某个对象状态的工具方法；
- 程序入口 `main`。

不要把所有字段都改成 `static`。例如每个用户的姓名、每个任务的状态都属于具体记录，通常应是实例字段。把它们做成静态字段，会让不同对象共享同一份数据，造成数据互相覆盖。

**本节先记住：**不带 `static` 的实例成员属于对象；带 `static` 的成员属于类。静态方法没有 `this`，不能直接访问实例成员。

## 5　`final`：限制重新赋值，不等于所有内容都不可变

### 5.1 `final` 修饰变量

```java
final int maxMembers = 8;
maxMembers = 10; // 编译错误
```

`final` 限制这个变量只能完成一次赋值。它可以在声明时初始化，也可以先声明、再在使用前完成一次赋值：

```java
final int maxMembers;
maxMembers = 8;
System.out.println(maxMembers);
```

但不能赋值两次。对于成员字段，空白 `final` 字段通常要在声明处或构造方法中完成初始化，确保对象创建完成时它已经有值。

### 5.2 `final` 修饰引用变量时，限制的是引用

这是很容易误解的地方：

```java
final StringBuilder builder = new StringBuilder("Hello");
builder.append(" Java");                 // 允许：修改对象内部内容
builder = new StringBuilder("World");   // 编译错误：不能重新指向另一个对象
```

`final` 限制 `builder` 不能重新赋值，不代表它指向的对象一定不可变。

对比：

- `final` 引用：不能让这个变量改为引用另一个对象；
- 不可变对象：对象创建后，内部状态也不能改变。

这是两个不同概念。`String` 是不可变对象；`StringBuilder` 是可变对象。即使引用是 `final`，`StringBuilder` 仍然可以追加内容。

### 5.3 `final` 还能修饰方法和类

```java
final class Utility {
    // 这个类不能被其他类继承
}

class Parent {
    final void printRule() {
        System.out.println("固定规则");
    }
}
```

- `final` 修饰类：这个类不能被继承。
- `final` 修饰方法：子类不能重写这个方法。
- `final` 修饰变量：这个变量不能再次赋值。

### 5.4 `static final` 常量

```java
class TaskRules {
    static final int MAX_RETRY = 3;
}
```

这里 `static` 表示属于类，`final` 表示不能重新赋值。常量通常通过类名访问，命名惯例使用大写字母和下划线：`TaskRules.MAX_RETRY`。

**本节先记住：**`final` 的核心是限制重新赋值或继承/重写行为，不要把“引用不能改”和“对象内部不能改”混为一谈。

## 6　封装与 Getter / Setter：不要让外部随意修改对象内部数据

### 6.1 为什么需要封装？

如果字段直接公开：

```java
class Member {
    int age;
}
```

外部可以随意写：

```java
Member member = new Member();
member.age = -100;
```

语法上没有问题，但业务数据不合理。封装的思路是：把内部数据隐藏起来，只开放经过设计的访问入口。

```java
class Member {
    private int age;
}
```

`private` 表示这个字段只能在 `Member` 类内部直接访问，外部不能写 `member.age`。这时可以按需要提供 Getter 和 Setter。

### 6.2 Getter：读取字段

```java
class Member {
    private String name;

    public String getName() {
        return name;
    }
}
```

`getName()` 是一个普通方法：`public` 表示外部可以调用，`String` 是返回值类型，`return name` 把当前对象的字段值交给调用者。

外部这样读取：

```java
Member member = new Member();
String name = member.getName();
```

### 6.3 Setter：修改字段

```java
class Member {
    private int age;

    public void setAge(int age) {
        if (age < 0 || age > 150) {
            throw new IllegalArgumentException("年龄不合法");
        }
        this.age = age;
    }
}
```

`setAge` 接收一个参数，检查合法性后再修改字段。外部调用：

```java
member.setAge(24);
```

如果传入 `-100`，就会抛出异常，而不是把非法数据写进去。这里的 `throw` 和异常类型会在后续异常处理章节系统学习；现在先理解 Setter 可以成为统一校验入口。

### 6.4 Getter / Setter 的常见命名

JavaBeans 生态中常见的命名约定是：

| 作用 | 常见命名 | 示例 |
| --- | --- | --- |
| 读取普通属性 | `get` + 属性名 | `getName()`、`getAge()` |
| 修改属性 | `set` + 属性名 | `setName(...)`、`setAge(...)` |
| 读取布尔属性 | 常见 `is` + 属性名 | `isActive()` |

这些名字不是 Java 关键字，而是约定。框架、IDE 和工具常按这套规则识别属性。

### 6.5 不是每个字段都必须同时有 Getter 和 Setter

Getter 和 Setter 不是为了凑数量，而是为了表达允许的访问方式：

- 只读数据：可以只提供 Getter；
- 需要校验后修改：提供 Setter，并在里面检查；
- 不希望外部访问：保持 `private`，不提供 Getter / Setter；
- 创建后不允许重新赋值：可以使用 `private final` 字段，在构造方法中初始化，只提供 Getter。

例如成员报告中的姓名和待办数可以作为一次性快照：

```java
class Member {
    private final String name;
    private final int remaining;

    Member(String name, int remaining) {
        this.name = name;
        this.remaining = remaining;
    }

    public String getName() {
        return name;
    }

    public int getRemaining() {
        return remaining;
    }
}
```

这里没有 Setter，因为对象创建后不允许外部再修改这两个字段。

### 6.6 四种访问修饰符

访问修饰符决定其他代码能否访问类、字段、构造方法和方法。先掌握下面四种：

| 修饰符 | 常见称呼 | 同一个类 | 同一个包的其他类 | 不同包的子类 | 不同包的非子类 |
| --- | --- | --- | --- | --- | --- |
| `public` | 公共 | 可以 | 可以 | 可以 | 可以 |
| `protected` | 受保护 | 可以 | 可以 | 可以* | 不可以 |
| 不写 | 包级 / 默认访问 | 可以 | 可以 | 不可以 | 不可以 |
| `private` | 私有 | 可以 | 不可以 | 不可以 | 不可以 |

`protected` 在不同包的子类中有额外的访问规则：子类可以访问继承得到的受保护成员，但不能把它当成任意对象都可访问的公共成员。初学阶段先记住“同包可访问；跨包需要处于子类访问场景”，更细的限定会在包与继承练习中验证。

不写访问修饰符并不等于 `public`，它表示包级访问（package-private）：同一个包中的其他类可以访问，不同包不能直接访问。

### 6.7 `package` 和 `import` 先认识到什么程度？

包（package）用于组织类，并形成命名空间。例如：

```java
package study.members;
```

通常放在 Java 源文件开头。两个类如果声明在同一个包中，就属于同一个包；如果包名不同，就是不同包。

`import` 用来导入其他包中的类型，让代码可以使用短类名。例如：

```java
import java.util.List;
```

这样可以写 `List<Member>`，而不用每次都写完整名称 `java.util.List<Member>`。`import` 不会把另一个类的代码复制进当前文件。

本节示例为了减少干扰，大多放在默认包中。包目录、编译输出和类路径的关系会在第 04 节进一步学习。

**本节先记住：**封装不是机械地给每个字段生成 get/set，而是控制外部如何读取和修改对象状态；`private` 隐藏内部字段，公开的方法提供受控入口。

## 7　继承：把多个类的共同部分放到父类

### 7.1 为什么需要继承？

假设系统中有学生和老师，两者都有姓名、年龄和自我介绍行为。如果每个类都重复声明这些内容，维护起来会很麻烦。可以把共同部分放到 `Person` 类中，再让具体类继承它。

```java
class Person {
    String name;
    int age;

    void introduce() {
        System.out.println("我是" + name);
    }
}

class Student extends Person {
    void study() {
        System.out.println(name + " 正在学习");
    }
}

class Teacher extends Person {
    void teach() {
        System.out.println(name + " 正在教学");
    }
}
```

`extends` 表示继承。`Student` 和 `Teacher` 是子类，`Person` 是父类。

```java
Student student = new Student();
student.name = "小林";
student.age = 24;
student.introduce();
student.study();
```

虽然 `Student` 没有声明 `name`、`age` 和 `introduce()`，但它继承了父类中可访问的成员。

### 7.2 子类继承了什么？

可以先这样理解：子类对象具有父类中可继承的状态和行为，也可以增加自己的字段和方法，或者重写父类允许重写的方法。

但要注意：

- `private` 成员仍然属于父类定义的对象状态，子类不能直接用字段名访问它；
- 构造方法不会被子类继承；
- 父类的构造方法负责初始化父类部分，子类构造方法负责初始化子类部分。

### 7.3 `super`：访问父类成员、调用父类构造方法

```java
class Person {
    String name;

    Person(String name) {
        this.name = name;
    }
}

class Student extends Person {
    int studentId;

    Student(String name, int studentId) {
        super(name);
        this.studentId = studentId;
    }
}
```

`super(name)` 调用父类的构造方法，把姓名交给 `Person` 初始化。它必须放在子类构造方法的第一条语句位置。

如果子类构造方法没有显式写 `super(...)`，编译器会尝试插入无参的 `super()`。因此，如果父类没有可用的无参构造方法，子类就必须显式调用一个匹配的父类构造方法。

`super` 也可以用于调用父类中被子类重写的方法，例如 `super.introduce()`。

### 7.4 方法重写（Override）

子类可以为继承来的实例方法提供自己的实现：

```java
class Person {
    void introduce() {
        System.out.println("我是一个人");
    }
}

class Student extends Person {
    @Override
    void introduce() {
        System.out.println("我是一名学生");
    }
}
```

`@Override` 是注解，用来告诉编译器“我打算重写父类方法”，编译器会帮忙检查方法签名是否匹配。它不是必须写的语法，但强烈建议写。

重写时不能把父类公开的方法改成更窄的访问权限。例如父类方法是 `public`，子类重写时也必须保持 `public`。

### 7.5 重载和重写不要混淆

| 概念 | 英文 | 发生位置 | 关键区别 |
| --- | --- | --- | --- |
| 方法重载 | Overload | 通常同一个类中，也可能发生在继承关系中 | 方法名相同，参数列表不同 |
| 方法重写 | Override | 父类与子类之间 | 子类重新实现继承来的实例方法，方法签名需要匹配 |

### 7.6 Java 普通类只能单继承

下面不允许：

```java
class TeachingAssistant extends Student, Teacher {
}
```

一个普通类只能通过 `extends` 继承一个直接父类。但它可以实现多个接口，后面会讲到。

**本节先记住：**继承用 `extends`，适合表达“子类是一种父类”；`super` 用来处理父类部分；`@Override` 标记方法重写。Java 普通类只能单继承。

## 8　抽象类：有共同基础，但不应该直接创建的类

### 8.1 为什么需要抽象类？

假设所有动物都有名字，也都能睡觉，但不同动物的叫声不同。可以把共同属性和共同实现放进一个抽象类，把必须由具体动物决定的行为留给子类。

```java
abstract class Animal {
    String name;

    void sleep() {
        System.out.println(name + " 正在睡觉");
    }

    abstract void makeSound();
}
```

`abstract` 表示抽象。`makeSound()` 只有方法声明，没有方法体，是抽象方法；`sleep()` 有具体实现，是普通实例方法。

### 8.2 抽象类不能直接创建对象

```java
Animal animal = new Animal(); // 编译错误
```

因为 `Animal` 只是一个不完整的抽象定义，不能直接实例化。可以让具体子类继承它，并实现抽象方法：

```java
class Dog extends Animal {
    @Override
    void makeSound() {
        System.out.println("汪汪");
    }
}
```

然后：

```java
Dog dog = new Dog();
dog.name = "小白";
dog.makeSound();
dog.sleep();
```

预期输出：

```text
汪汪
小白 正在睡觉
```

### 8.3 抽象类可以有什么？

抽象类不是“只能写抽象方法的类”。它可以拥有：

- 普通成员字段；
- 构造方法；
- 已经实现的普通方法；
- 尚未实现的抽象方法。

如果一个子类没有实现父抽象类中所有需要实现的抽象方法，那么这个子类也必须声明为 `abstract`，不能作为完整的具体类直接创建对象。

### 8.4 什么时候考虑抽象类？

当几个类确实属于同一类事物，并且需要共享字段、构造逻辑或部分方法实现时，可以考虑抽象类。例如 `Animal`、`Person`、`BaseTaskHandler`。

抽象类仍然遵循类的单继承限制：一个类只能 `extends` 一个类（普通类或抽象类）。下一节的接口则更适合描述可由不同类型对象具备的能力。

## 9　接口：定义能力和规范，不限定具体实现

### 9.1 用“支付能力”理解接口

假设支付宝、微信和银行卡的内部实现不同，但业务系统希望它们都提供支付能力。可以先定义规范：

```java
interface Payment {
    void pay(double amount);
}
```

`interface` 用来定义接口。这里声明了一个 `pay` 方法，表示实现者需要提供支付行为。

### 9.2 类通过 `implements` 实现接口

```java
class Alipay implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("支付宝支付：" + amount);
    }
}

class WechatPay implements Payment {
    @Override
    public void pay(double amount) {
        System.out.println("微信支付：" + amount);
    }
}
```

`implements Payment` 表示这个类承诺实现 `Payment` 接口。接口中普通抽象方法默认是 `public abstract`，所以实现方法必须是 `public`，不能降低访问权限。

### 9.3 为什么接口能降低耦合？

业务代码可以依赖接口，而不是写死某个支付类：

```java
class OrderService {
    void checkout(Payment payment) {
        payment.pay(100);
    }
}
```

调用时传入不同实现：

```java
OrderService service = new OrderService();
service.checkout(new Alipay());
service.checkout(new WechatPay());
```

`OrderService` 只知道 `Payment` 规定了 `pay()`，不需要知道内部是支付宝还是微信。以后新增 `BankCardPay implements Payment`，业务方法通常不需要改动。

这就是**面向接口编程**的基本思想：业务依赖稳定的规范，具体实现可以替换。

### 9.4 接口里可以写什么？

Java 接口不只是“只能写方法声明”。现代 Java 接口可以包含抽象方法、常量，以及带实现的方法。

**普通抽象方法：**

```java
interface Payment {
    void pay(double amount);
}
```

没有写修饰符的普通接口方法，默认相当于 `public abstract`。

**常量：**

```java
interface Payment {
    int MAX_AMOUNT = 10000;
}
```

接口中的字段默认都是 `public static final`，也就是公开、属于接口本身、不能重新赋值的常量。接口不能定义每个实现对象各自拥有的普通实例字段，也没有构造方法。

**`default` 方法：**

```java
interface Payment {
    void pay(double amount);

    default void printReceipt() {
        System.out.println("支付凭证已生成");
    }
}
```

`default` 方法有方法体，并且默认是 `public`。实现类不重写时，可以直接使用这个默认实现；也可以根据需要重写。它是实例方法，可以通过实现类对象调用。

**`static` 方法：**

```java
interface Payment {
    static void printHelp() {
        System.out.println("支付帮助");
    }
}
```

通过接口名调用：

```java
Payment.printHelp();
```

接口中未显式写访问修饰符的静态方法默认是 `public`。静态方法属于接口本身，通过接口名调用，不会作为普通实例方法被实现类继承。

**`private` 方法：**

Java 9 起，接口可以定义 `private` 方法，供接口内部的 `default` 或 `static` 方法复用。它不能被接口外部或实现类直接调用。初学阶段知道有这项能力即可。

### 9.5 一个类可以实现多个接口

```java
interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

class Duck implements Flyable, Swimmable {
    @Override
    public void fly() {
        System.out.println("鸭子在飞");
    }

    @Override
    public void swim() {
        System.out.println("鸭子在游泳");
    }
}
```

一个类可以通过逗号实现多个接口：

```java
class Duck extends Animal implements Flyable, Swimmable {
    @Override
    void makeSound() {
        System.out.println("嘎嘎");
    }

    @Override
    public void fly() {
        System.out.println("鸭子在飞");
    }

    @Override
    public void swim() {
        System.out.println("鸭子在游泳");
    }
}
```

接口也可以继承多个接口：

```java
interface FlyingAndSwimming extends Flyable, Swimmable {
}
```

所以要区分：一个类只能 `extends` 一个类，但可以 `implements` 多个接口。

### 9.6 Java 接口和 TypeScript 接口有什么区别？

你之前用过 TypeScript，语法看起来很相似，但两者底层的类型机制并不相同。

**TypeScript：主要是结构化类型。**

```typescript
interface Payment {
    pay(amount: number): void;
}

class Alipay {
    pay(amount: number): void {
        console.log("支付宝支付");
    }
}

const payment: Payment = new Alipay();
```

即使 `Alipay` 没有写 `implements Payment`，只要结构满足接口要求，通常仍然可以赋值给 `Payment` 类型。这是因为 TypeScript 主要检查对象是否具有需要的成员。

**Java：主要是名义类型关系。**

```java
interface Payment {
    void pay(double amount);
}

class Alipay {
    public void pay(double amount) {
        System.out.println("支付宝支付");
    }
}
```

虽然 `Alipay` 有同名同参数的方法，但没有声明 `implements Payment`，就不能直接写：

```java
Payment payment = new Alipay(); // 编译错误
```

Java 要求通过 `implements` 明确建立接口实现关系。

再看几个关键差异：

| 对比 | TypeScript interface | Java interface |
| --- | --- | --- |
| 主要类型机制 | 结构化类型：看成员结构是否兼容 | 主要是名义类型：看是否声明了实现/继承关系 |
| 编译后是否保留接口定义 | 通常会擦除，不作为 JavaScript 运行时接口存在 | 接口类型信息保留在 `.class` 中，JVM 运行时可识别 |
| 能否作为变量类型 | 可以 | 可以 |
| 能否要求类实现规范 | `implements` 可做编译期检查 | `implements` 建立真实类型关系 |
| 默认方法实现 | interface 本身不提供 Java 式实例默认方法体 | 支持 `default` 方法 |

例如 Java 可以在运行时判断：

```java
Payment payment = new Alipay();
System.out.println(payment instanceof Payment); // true
```

TypeScript 的接口定义在编译后会被擦除，因此不能直接用 JavaScript 的 `instanceof` 判断一个对象是否实现了某个 TS interface。需要运行时判断时，通常要检查实际字段、使用类或自行保留标记。

### 9.7 抽象类和接口怎么选？

| 对比 | 抽象类 | 接口 |
| --- | --- | --- |
| 核心目的 | 提供一组相关类的共同基础 | 定义能力、规范或可替换的契约 |
| 继承/实现关键字 | `extends` | `implements` |
| 普通实例字段 | 可以 | 不可以 |
| 构造方法 | 可以 | 不可以 |
| 抽象方法 | 可以 | 可以 |
| 具体方法 | 可以 | 可以通过 `default` 等方式提供 |
| 数量限制 | 一个类只能继承一个类 | 一个类可以实现多个接口 |
| 典型关系 | `Student` 是一种 `Person` | `Duck` 具备 `Flyable` 能力 |

简单记忆：抽象类偏向“是什么”（is-a），接口偏向“能做什么”（can-do）。这不是绝对规则，真正设计时还要看共享状态、实现复用和替换需求。

**本节先记住：**接口用 `interface` 定义、用 `implements` 实现；一个类可以实现多个接口。接口是 Java 运行时也认识的类型，不等同于 TypeScript 只在编译阶段存在的 interface。

## 10　多态：同一种调用，可以执行不同实现

### 10.1 先看接口类型的变量

前面有：

```java
Payment payment = new Alipay();
payment.pay(100);
```

这里左边的 `Payment` 是变量声明类型，右边创建的实际对象是 `Alipay`。

这行代码是允许的，因为 `Alipay` 实现了 `Payment`。接口类型的变量可以引用任意实现该接口的对象。

### 10.2 为什么执行的是 Alipay 的方法？

如果再写：

```java
Payment payment = new WechatPay();
payment.pay(100);
```

调用形式没有变，执行结果却会根据实际对象不同而不同：

- 实际对象是 `Alipay`，执行 `Alipay.pay()`；
- 实际对象是 `WechatPay`，执行 `WechatPay.pay()`。

这就是多态的一种典型表现：**父类或接口类型的引用，指向不同的子类或实现类对象；调用被重写的方法时，运行时根据实际对象选择实现。**

### 10.3 编译时看引用类型，运行时看实际对象

```java
Payment payment = new Alipay();
payment.pay(100);
```

- 编译时：编译器根据左边的 `Payment` 检查 `pay()` 是否存在、参数是否匹配。
- 运行时：JVM 根据右边实际创建的 `Alipay` 对象，执行它的 `pay()` 实现。

因此，如果 `Alipay` 还有一个独有方法 `refund()`，但 `Payment` 接口没有声明它：

```java
payment.refund(); // 编译错误
```

即使实际对象确实是 Alipay，编译器也不会允许通过 `Payment` 类型的变量直接调用接口没有声明的方法。

### 10.4 向上转型和向下转型

**向上转型（Upcasting）：**把子类对象交给父类或接口类型变量。通常可以自动完成：

```java
Alipay alipay = new Alipay();
Payment payment = alipay;
```

**向下转型（Downcasting）：**如果确实需要使用子类独有的能力，可以把父类/接口引用转回具体子类类型，但必须确保实际对象确实是该类型：

```java
Payment payment = new Alipay();
Alipay alipay = (Alipay) payment;
```

如果实际对象是 `WechatPay`，却强制转换成 `Alipay`，运行时会抛出 `ClassCastException`。

### 10.5 用 `instanceof` 先判断类型

```java
if (payment instanceof Alipay) {
    Alipay alipay = (Alipay) payment;
    // 这里可以使用 Alipay 独有的方法
}
```

JDK 21 还支持模式匹配写法：

```java
if (payment instanceof Alipay alipay) {
    // 判断成功后，alipay 已经是 Alipay 类型的变量
}
```

它把“类型判断”和“转换后变量”合并在一起，减少重复代码。

不过，业务代码如果到处判断 `instanceof`，往往说明抽象设计可能不够合适。能通过接口声明统一行为时，通常优先直接调用接口方法，而不是先判断具体类型再分支。

### 10.6 多态为什么有用？

再看业务服务：

```java
class OrderService {
    void checkout(Payment payment) {
        payment.pay(100);
    }
}
```

它不需要知道传入的是支付宝、微信还是银行卡。只要对象遵守 `Payment` 规范，就能完成支付。

多态让调用方依赖抽象规范，具体实现可以替换。这是接口、继承和面向接口编程能够配合工作的关键。

**本节先记住：**变量声明类型决定“编译时允许调用什么”；实际对象类型决定“运行时执行哪个重写实现”。向下转型前要确认实际对象类型，不能盲目强转。

## 11　把多个对象放进 `List<Member>`

现在回到本节最初的问题：已经能创建一个成员对象，怎样管理一组成员？

### 11.1 数组和 List 的区别

数组和列表都能按顺序保存多个元素，并通过下标访问，但使用方式不同：

| 对比 | 数组 | `List` |
| --- | --- | --- |
| 长度 | 创建后固定 | 常见实现可以动态增删 |
| 长度/元素数量 | `array.length` | `list.size()` |
| 读取元素 | `array[0]` | `list.get(0)` |
| 添加元素 | 不能直接扩容 | `list.add(...)`（取决于具体列表是否可修改） |
| 常见声明 | `Member[] members` | `List<Member> members` |

### 11.2 `List` 是接口，`ArrayList` 是具体实现类

```java
List<Member> team = new ArrayList<>();
```

这里有三个知识点：

- `List` 是接口，规定列表常见的操作，例如 `add`、`get`、`size`；
- `ArrayList` 是实现 `List` 接口的具体类，提供了基于数组的列表实现；
- `new ArrayList<>()` 创建具体对象，左边使用接口类型接收它。

这和前面学的 `Payment payment = new Alipay()` 是同一种类型关系：左边用接口类型，右边创建实现类对象。

需要导入：

```java
import java.util.ArrayList;
import java.util.List;
```

### 11.3 `List<Member>` 中的尖括号是什么意思？

`List<Member>` 表示这是一个元素类型为 `Member` 的列表。它属于泛型语法，作用是约束列表里能放什么类型的元素。

```java
List<Member> team = new ArrayList<>();
team.add(new Member("小林", 3));
team.add(new Member("小周", 0));
team.add("小陈"); // 编译错误：String 不是 Member
```

Java 的泛型类型参数必须是引用类型，不能写 `List<int>`；如果要保存整数，使用包装类型 `List<Integer>`。泛型会在后续集合章节深入学习。

### 11.4 `List.of(...)` 与 `ArrayList` 的可修改性

```java
List<Member> team = List.of(
    new Member("小林", 3),
    new Member("小周", 0)
);
```

`List.of(...)` 适合创建一组已知、只读遍历的数据。它返回的列表不支持 `add`、`remove` 等结构修改操作。

如果确实需要增加或删除成员，可以创建 `ArrayList`：

```java
List<Member> team = new ArrayList<>();
team.add(new Member("小林", 3));
team.add(new Member("小周", 0));
team.add(new Member("小陈", 2));
```

也可以基于已有列表复制出可修改列表（这里复制的是元素引用，不是重新创建每个成员对象）：

```java
List<Member> editableTeam = new ArrayList<>(team);
```

**列表能不能增删**和**列表里的对象能不能修改字段**是两个不同问题。列表不可修改，不代表它里面的对象一定不可变；列表可以增删，也不代表每个成员对象的字段都可以随意修改。

### 11.5 遍历列表

```java
for (Member member : team) {
    System.out.println(member.getName());
}
```

这叫增强 `for` 循环，可以理解为“依次取出列表中的每个元素，暂时放进 `member` 变量”。`member` 每轮引用当前成员对象，因此可以调用它的实例方法。

## 12　综合示例：输出所有有待办的成员

前面分别学了对象、构造方法、封装、实例方法、静态常量和列表。现在把这些知识放在一个完整程序里。

新建完整文件 **`TeamReport.java`**：

```java
import java.util.List;

public class TeamReport {
    private static final String TEAM_NAME = "平台组";

    public static void main(String[] args) {
        List<Member> team = List.of(
                new Member("小林", 3),
                new Member("小周", 0),
                new Member("小陈", 2)
        );

        printPendingMembers(team);
    }

    private static void printPendingMembers(List<Member> team) {
        for (Member member : team) {
            if (member.hasPending()) {
                System.out.println(
                        member.getName() + " / " + TEAM_NAME
                                + " / 剩余 " + member.getRemaining()
                );
            }
        }
    }
}

class Member {
    private final String name;
    private final int remaining;

    Member(String name, int remaining) {
        if (remaining < 0) {
            throw new IllegalArgumentException("待办数不能为负数");
        }
        this.name = name;
        this.remaining = remaining;
    }

    public String getName() {
        return name;
    }

    public int getRemaining() {
        return remaining;
    }

    public boolean hasPending() {
        return remaining > 0;
    }
}
```

在 PowerShell 中执行：

```powershell
java TeamReport.java
```

预期输出：

```text
小林 / 平台组 / 剩余 3
小陈 / 平台组 / 剩余 2
```

### 12.1 沿着一次调用读完整个程序

1. 启动器执行 `TeamReport.main()`，程序从入口开始。
2. `List.of(...)` 创建一个只读列表，里面有三个 `Member` 对象。
3. 每次执行 `new Member("小林", 3)`，都会创建一个对象并调用对应构造方法。
4. 构造方法先检查待办数是否合法，再通过 `this.name`、`this.remaining` 初始化当前对象字段。
5. 字段是 `private final`，外部不能直接访问，也不能通过 Setter 重新赋值；读取时通过公开 Getter。
6. `printPendingMembers(team)` 是静态方法，因此通过 `TeamReport` 类的执行上下文调用，不需要创建 `TeamReport` 对象。
7. 增强 `for` 每轮把一个成员对象引用交给局部变量 `member`。
8. `member.hasPending()` 是实例方法，读取当前对象的 `remaining`，返回是否大于 0。
9. 只有返回 `true` 的成员才打印，因此小周不会出现在输出中。

### 12.2 这里分别用到了哪些知识？

| 代码 | 对应知识 | 为什么这样写 |
| --- | --- | --- |
| `public class TeamReport` | 类 | 定义程序入口和报告行为 |
| `main(...)` | 静态入口方法 | 让启动器可以启动程序 |
| `static final String TEAM_NAME` | 静态常量 | 团队名称由报告类共享，且不允许重新赋值 |
| `new Member(...)` | 对象与构造方法 | 创建成员并一次性初始化必要数据 |
| `private final` | 封装与 final | 隐藏字段，创建后不允许重新赋值 |
| `getName()` | Getter | 对外提供只读访问 |
| `hasPending()` | 实例方法 | 由成员对象根据自己的数据回答问题 |
| `List<Member>` | 接口与泛型 | 通过 List 类型管理一组 Member |
| `List.of(...)` | 列表工厂方法 | 创建固定内容的只读列表 |

### 12.3 观察两种不同的失败

**实验 A：传入非法待办数。**把其中一个构造参数从 `3` 改成 `-3`，重新运行。预期程序在创建该成员时抛出 `IllegalArgumentException`，不会正常打印完整报告。恢复为非负数。

**实验 B：尝试修改只读列表。**在 `List.of(...)` 创建列表之后加入：

```java
team.add(new Member("小吴", 1));
```

代码可以通过编译，但运行时预期抛出 `UnsupportedOperationException`，因为 `List.of` 返回的列表不支持增加元素。删除这行即可恢复。如果业务需要动态增删，应改用 `new ArrayList<>()`。

再试着写 `team.add("小吴")`：这次是编译错误，因为 `List<Member>` 不接受 `String`。一个是列表本身不允许修改，一个是元素类型不符合要求，失败发生的阶段不同。

## 13　常见问题集中辨析

| 容易混淆的概念 | 正确区分 |
| --- | --- |
| 类与对象 | 类描述一类对象；对象是类的具体实例 |
| 声明引用与创建对象 | `Member member;` 只是声明变量；`new Member()` 才创建对象 |
| 两个引用与两个对象 | `a = new Member(); b = new Member();` 是两个对象；`b = a` 是两个引用指向同一对象 |
| 构造方法与普通方法 | 构造方法与类同名且不写返回类型；普通方法有返回类型（可以是 `void`） |
| 构造方法与 `main` | 构造方法初始化对象；`main` 是启动指定类时使用的入口 |
| 实例字段与静态字段 | 实例字段每个对象一份；静态字段整个类共享一份 |
| `final` 引用与不可变对象 | `final` 限制引用变量重新赋值；不保证引用指向的对象不可变 |
| Getter / Setter 与封装 | Getter / Setter 是常见访问入口；封装的核心是控制外部访问和修改方式 |
| 重载与重写 | 重载看参数列表不同；重写是子类重新实现继承来的方法 |
| 抽象类与接口 | 抽象类提供共同基础；接口定义能力和规范 |
| 接口类型与具体实现类 | 接口变量可以引用实现类对象；编译时按接口检查可调用成员 |
| `List` 与 `ArrayList` | `List` 是接口；`ArrayList` 是它的一种具体实现 |
| 列表不可修改与元素不可变 | 一个限制列表结构增删，一个限制对象自身状态变化 |

## 本节小结与下一节

本节从“把多个数组中的数据放在一起”开始，逐步建立了 Java 面向对象的基本模型：

1. **类与对象：**类描述结构，对象是实例，引用变量用来找到对象。
2. **构造方法：**在创建对象时初始化数据；名称与类名相同，没有返回类型。
3. **实例成员与静态成员：**实例成员属于对象，静态成员属于类。
4. **封装：**使用访问修饰符控制访问，通过方法提供受控入口。
5. **继承与抽象：**提取共同基础，允许子类扩展或实现抽象行为。
6. **接口与多态：**用规范隔离具体实现，让同一种调用适配不同对象。
7. **集合：**使用 `List<Member>` 管理多个成员对象。
