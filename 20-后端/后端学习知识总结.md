# 二、Node.js 基础

## 1. HTTP Server

Node 原生 HTTP 流程：

    TCP连接
     ↓
    HTTP Request
     ↓
    Node HTTP Server
     ↓
    (req,res)
     ↓
    Response

核心对象：

## req

IncomingMessage：

负责：

-   请求信息
-   headers
-   method
-   url
-   body stream

## res

ServerResponse：

负责：

-   设置状态码
-   设置响应头
-   返回数据

例如：

``` ts
res.writeHead(200)
res.end()
```

------------------------------------------------------------------------

# 三、Request Body

Node 原生没有：

``` ts
req.body
```

请求体本质：

    HTTP Body
     ↓
    chunks
     ↓
    Buffer
     ↓
    Buffer.concat
     ↓
    string
     ↓
    JSON.parse
     ↓
    object

Express：

``` ts
express.json()
```

本质是帮我们完成：

-   读取 stream
-   合并 Buffer
-   JSON解析

# 四、Stream

学习内容：

-   Readable
-   Writable
-   Duplex
-   Transform

核心思想：

> 不要一次性把大量数据加载到内存。

例如：

文件传输：

``` ts
createReadStream(file).pipe(res)
```

优势：

-   降低内存占用
-   支持大文件处理

理解：

## Backpressure

当生产速度大于消费速度时：

需要控制流速。

------------------------------------------------------------------------

# 五、Event Loop

理解：

Node.js 单线程并不是所有任务都由一个线程完成。

## I/O Bound

等待外部资源：

-   MySQL
-   Redis
-   HTTP
-   文件
-   Socket

## CPU Bound

大量计算：

-   图片处理
-   压缩
-   加密
-   算法计算

CPU密集任务不适合阻塞主线程。

------------------------------------------------------------------------

# 六、Worker Thread

用途：

处理 CPU 密集任务。

结构：

    主线程

     ↓ message

    Worker

     ↓

    计算完成

     ↓ message

    主线程

理解：

postMessage 和 done：

都是应用层定义的消息协议。

不是 Node 内置关键字。

# 十四、主键 PK

作用：

唯一标识记录。

例如：

    users

    id=100

    id

------------------------------------------------------------------------

# 十五、外键 FK

作用：

保证引用关系。

例如：

    tasks.project_id

    ↓

    projects.id

外键保证：

项目存在。

但是不能保证业务规则：

例如：

用户是否属于项目。

这个需要 Service 判断。

------------------------------------------------------------------------

# 十六、数据库关系设计

## 一对多

规则：

例如：

    projects

## 多对多

# 十七、范式

## 第一范式

字段不可存多个值。

错误：

    role_ids="1,2,3"

------------------------------------------------------------------------

## 第二范式

联合主键情况下：

字段应该依赖完整主键。

------------------------------------------------------------------------

## 第三范式

避免：

非主键字段依赖非主键字段。

------------------------------------------------------------------------

# 十八、索引

索引作用：

提高查询速度。

不是：

所有字段都建立索引。

成本：

-   增加存储
-   降低写入速度
-   增加维护成本

本质：

> 用写入成本换查询性能。

------------------------------------------------------------------------

# 十九、EXPLAIN

作用：

查看SQL执行计划。

关注：

## type

访问方式。

## key

实际使用索引。

## rows

预计扫描行数。

实验：

无索引：

    全表扫描

建立：

``` sql
CREATE INDEX idx_project_id
ON tasks(project_id);
```

之后：

    type=ref

    key=idx_project_id

    rows明显降低
