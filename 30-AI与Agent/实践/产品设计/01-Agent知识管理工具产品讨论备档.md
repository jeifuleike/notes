## 1. 项目缘起

用户希望开发一个 Agent 项目作为练手作品，约束条件：

- **单人开发**，希望开发周期短
- 有一定**创新性**
- **日常能用得到**
- 核心目标是**学习 Agent 开发**（Prompt → Tool Use → RAG → ReAct → Multi-Agent）

## 3. 产品方向演进

### 3.1 第一阶段：AI 日记助手

用户最初选择"AI 日记助手"，首次输出了四版本规划（v0.1 萌芽 → v0.2 成长 → v0.3 绽放 → v1.0 森林）。

### 3.2 第二阶段：扩展为「日记 + 笔记管理」

用户反馈日记功能太简单，要求扩展为更综合的工具，新增需求：

- **笔记存储**：不仅是日记，还支持通用笔记的创建和存储
- **自动笔记归纳优化**：Agent 主动对笔记进行分类、标签、关联、摘要
- **笔记管理员角色**：Agent 扮演"笔记管家"，负责组织、归档、清理冗余
- **知识库总结查询/二次输出**：基于知识库内容重新组合/总结/提炼，输出新的结构化内容
- **全本地输出**：在指定文件夹输出 .md 或 .txt 文件

| # | 决策项 | 结论 |
|---|--------|------|

## 5. 产品定位

> **「Code as Notebook」— 一个用 AI Agent 帮你自动整理本地 Markdown 笔记的极简桌面工具。你只管写，它帮你管。**

### 5.1 目标用户画像

| 维度 | 描述 |
|------|------|
| 身份 | 全栈/前端开发者，TypeScript 为主 |
| 工作模式 | 个人项目 + 持续学习，有较强的笔记/文档需求 |
| 笔记习惯 | 习惯用 Markdown 随手记，文件散落在不同项目文件夹里 |
| 工具偏好 | 本地工具、命令行友好，不信任云端笔记隐私和速度 |
| AI 使用 | 已在用 ChatGPT/Copilot，对「AI 主动整理」有期待 |
| 核心诉求 | 笔记不白写——写了能回顾、能被 AI 二次加工产生价值 |

> **第一用户即开发者本人**，后续可扩展到知识工作者。

### 5.2 核心竞争力

**核心缺口**：没有一个 **本地优先 + AI Agent 主动管理 + 极简 + 程序员可定制** 的笔记方案。

### 5.3 竞品差异化

| 工具 | 问题 |
|------|------|
| Notion | 云端、重、慢，Markdown 支持弱 |
| Obsidian | 强但学习成本高，AI 插件只是问答，不主动管理 |
| 印象笔记 | 老派、闭源、AI 功能弱 |
| 纯文件夹 + VS Code | 零 AI，纯手工作业 |
| Reflect.app / Mem.ai | 云端、订阅制、不可定制 |

## 6. 核心痛点（4 个）

### 痛点一：笔记写了等于没写（「记录-遗忘」循环）

写了一堆 Markdown → 文件夹越堆越多 → 再也没打开过。现有工具是被动的容器。

**需要**：Agent 定期帮你回顾、总结、关联，让旧笔记「复活」。

### 痛点二：笔记散落，找的时候靠 grep（分散管理）

笔记散落在不同项目/目录下，只能靠文件名和全局搜索，搜不到「概念」（如搜「React 性能优化」但笔记写的是「useMemo 优化」）。

**需要**：语义搜索 + AI 自动归类，不依赖手动建文件夹和打标签。

### 痛点三：从笔记到产出中间真空（「整理断层」）

碎片笔记 → （缺失环节）→ 可用的文档/文章/总结。手动整理耗时且不常做。

**需要**：Agent 自动把相关笔记聚合并重新输出为结构化内容。

### 痛点四：现有工具「太重」或「AI 不够深」

见上方竞品对比表。

## 7. 典型使用场景

### 场景一：每日随手记 → 周末自动回顾

- 周一~周五：每天打开 App，随手写几条，不需要组织结构
- 周日晚：Agent 自动生成「本周回顾」，用户花 5 分钟浏览

**价值**：把「记」和「回顾」解耦——记时零摩擦，回顾由 Agent 驱动。

### 场景二：学新技术 → 知识自动沉淀

- 在学新技术（如 Rust），看了教程、记了笔记，散落在文件夹下
- 对 Agent 说：「帮我整理 Rust 学习笔记」
- Agent 输出：已掌握的概念、不清楚的概念、结构化总结、关联旧笔记

### 场景三：碎片笔记 → 专题输出

- 几个月积累了大量某主题的零散笔记
- 对 Agent 说：「帮我把所有关于微前端的笔记整理成一篇文档」
- Agent 聚合输出结构化文档，用户在此基础上修改完善

## 8. 多版本 Agent 学习路线

因产品定位从「纯日记」扩展到「日记+笔记+知识库」，版本规划需重新设计，但 Agent 模式学习路线不变：

| 版本 | Agent 模式重点 | 说明 |
|------|---------------|------|
| v0.1 | Prompt 工程、LLM 调用封装、流式输出 | 跑通 Electron + TS 全栈闭环 |
| v0.2 | Tool Use (Function Calling)、结构化输出 (Zod)、RAG 入门 | 笔记开始有智能感 |
| v0.3 | Agent 自主规划、记忆管理、多步推理 (ReAct) | 真正的 Agent |
| v1.0 | Multi-Agent 协作、插件系统 | 可扩展产品 |

## 10. 关键约束（不变）

- 单人开发，周期可控
- Electron + React + TypeScript 全栈
- 桌面端，全本地运行

- 极简 UI 风格
