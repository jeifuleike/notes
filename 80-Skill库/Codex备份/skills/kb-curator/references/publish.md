# 发布

## 入口

只处理审核报告里被批准的条目。用户说“全部执行”时也要逐条核对，不扩大到报告之外。

## Preflight

对每条列出：

- 目标路径是否存在。
- 同名文件是否存在。
- 是新建、追加还是改写。
- 会更新哪些双链、导航或索引。
- 是否需要移动原始资料。

有冲突时停下来说明，不覆盖。

## 人读笔记

- 有同主题笔记：在原文件补充，保留原有结构和语气。
- 没有：按 `90-知识系统/模板/人读笔记.md` 新建。
- 标题和文件名遵循目标目录现有编号。
- 写入来源链接和更新日期。

## AI 操作卡

只有 L3/L4 才创建或更新：

- 放在 `70-AI知识资产/` 对应分区。
- 每张卡不超过 100 行。
- 固定五段：适用场景、必须遵守、禁止、检查清单、来源。
- `sources` 必须链接回人读笔记或来源笔记。

## 工作流规范

如果沉淀的是可重复流程：

- 放 `70-AI知识资产/工作流规范/`。
- 更新 `00-索引.md` 和 `70-AI知识资产/00-入口.md`。
- 只有流程稳定且需要自动化时，才在 `80-Skill库/候选/` 建 Skill 候选。

## 收尾

1. 追加 `90-知识系统/处理日志.md`。
2. 原始资料移到 `00-Inbox/已归档/YYYY-MM/`。
3. 检查新增双链是否可解析。
4. 展示 `git status` 和 `git diff --stat`。
5. 不自动提交。
