# 第 03 节　把成员姓名和待办数放在一起

上一节只知道有两个人有待办。不妨再问：**这两个人是谁？** 如果用两个数组分别存姓名和数量，只给其中一个排序，姓名就可能配错。我们让一个成员对象同时保存两项数据。

## 一张地图：一名成员和一组成员是两层问题

| 你想描述什么 | Java 中的名字 | 在本例里是什么 |
| --- | --- | --- |
| 一种事物可以有哪些数据、做什么 | 类；类中用字段记数据，用方法描述行为 | `Member`，有姓名、待办数，能回答自己是否有待办 |
| 某一个具体的人 | 对象（类的实例）；用引用变量找到它 | 小林和小周是不同的对象，不是两个类 |
| 新成员一开始应该具有什么数据 | 构造方法 | 创建时同时交给它姓名和数量，而不是日后凭记忆补填 |
| 多个人怎样排列和遍历 | `List<Member>`，元素为成员的有序列表 | 列表装的是成员引用，不是另一份姓名和数量 |

## 1　先创建一个人，不用列表

在空练习目录新建完整文件 `TeamReport.java`，用 JDK 21 执行 `java TeamReport.java`。一个文件里暂放两个类：排在前面的 `TeamReport` 负责启动，下面的 `Member` 负责描述成员。

```java
class TeamReport {
    public static void main(String[] args) {
        Member first = new Member();
        first.name = "小林";
        first.remaining = 3;
        System.out.println(first.name);
    }
}

class Member {
    String name;
    int remaining;
}
```

只打印「小林」。`Member first` 声明一个能引用成员的变量，`new Member()` 才真正创建对象。`first.name` 用点号选中这个人的字段。创建时字段有默认值：把设置姓名那行临时删掉，输出会变成 `null`，不是空字符串。改回去。只要创建与填写分成三行，就有漏设字段的机会。

## 2　把“先创建再填数据”改成“一次交齐数据”

先只替换文件末尾整个 `Member` 类：

```java
class Member {
    final String name;
    final int remaining;

    Member(String name, int remaining) {
        this.name = name;
        this.remaining = remaining;
    }
}
```

构造方法和类**同名且没有返回类型**，不是写成 `void Member(...)` 的普通方法。`this` 是这次正在初始化的对象：`this.name = name` 左边是它的字段，右边是传进来的参数。`final` 要求字段确定后不能再赋另一个值；适合本章的一次性报告快照，不表示所有业务对象都应如此设计。

这时旧的 `new Member()` 已经不匹配：之前没有声明任何构造方法，Java 提供了无参版本；现在你声明了带参版本，Java 不再替你提供无参版本。把 `main` 里“创建、设姓名、设数量”三行替换为一行 `Member first = new Member("小林", 3);`，保留原来的打印。再次运行，输出仍是「小林」。**结果没变，变的是调用者不再能漏传数量。** 这还没有检查数量是否非负：要求传值和验证值合法是不同的事。

## 3　让每个对象自己回答，再把多个对象放进列表

先在 `Member` 的最后一个右花括号前加入实例方法 `boolean hasPending() { return remaining > 0; }`。在 `main` 中只把打印内容从 `first.name` 换成 `first.hasPending()`。预期从姓名变成 `true`。把传入构造方法的 3 改成 0 再跑，结果变 `false`。括号里没有参数不是说它没有输入：点号左边的 `first` 已经指定它读**哪个对象**的字段。这一点和上一节接收整个数组的 `static` 方法不同。

一个人时 `first` 够用。三个人时，需要一个可逐个遍历的容器。数组和列表都保留顺序、从下标 0 开始；数组用 `team.length` 和 `team[0]`，列表用 `team.size()` 和 `team.get(0)`。`List` 是一组操作的约定（接口），不是要直接 `new List()` 的具体类；尖括号中的 `Member` 限定元素类型。`List.of(...)` 适合成员已知、只读遍历的报告；如果业务本来就要求动态增加成员，用 `new java.util.ArrayList<>(team)` 基于现有列表创建可增删的列表。列表是否可改，与元素的字段是否可改，是两个独立问题。

## 4　把“创建、判断、输出”连起来

以下是最终的**完整 `TeamReport.java`**。`import` 放在文件开头；先手算三个人中谁会被打印，再运行：

```java
import java.util.List;

class TeamReport {
    public static void main(String[] args) {
        List<Member> team = List.of(new Member("小林", 3),
                                    new Member("小周", 0),
                                    new Member("小陈", 2));
        for (Member member : team) {
            if (member.hasPending()) {
                System.out.println(member.name);
            }
        }
    }
}

class Member {
    final String name;
    final int remaining;

    Member(String name, int remaining) {
        this.name = name;
        this.remaining = remaining;
    }

    boolean hasPending() {
        return remaining > 0;
    }
}
```

运行 `java TeamReport.java`，预期先打印「小林」，下一行打印「小陈」。从 `new Member("小林", 3)` 跟一次：`Member` 是类，描述每个成员有哪些数据和行为；`new` 创建一个具体对象，调用与类同名的构造方法。`this.name = name` 把传入的姓名保存到这个对象的字段里；`final` 表示该字段赋值后不能重新赋值。

`import` 让代码能用短名 `List`；`List<Member>` 表示元素是成员对象的列表，`List.of` 把给出的对象组成不可增删的列表。循环里的 `member.hasPending()` 问的是**当前这个成员**，所以方法不需要再接收数量参数。TS 接口也能描述字段，但接口本身不能像这里的类一样用 `new` 创建实例。

| 本轮变量 `member` 指向谁 | `hasPending()` 读取什么 | 屏幕变化 |
| --- | --- | --- |
| 第一个成员 | 3 > 0，返回真 | 新增「小林」 |
| 第二个成员 | 0 > 0，返回假 | 不新增，也不会终止循环 |
| 第三个成员 | 2 > 0，返回真 | 新增「小陈」 |

**试错：**在循环前加入 `team.add(new Member("小吴", 1));`。类型没有问题，运行却预期报 `UnsupportedOperationException`，因为 `List.of` 返回的列表不支持添加元素。删掉这行即可恢复。再对比改为 `team.add("小吴");`：这次连运行都到不了，因为字符串不是 `Member`。两次都叫“加不了”，但一次是容器不支持操作，一次是元素类型不对。恢复原文件。

**自己写：**在 `List.of(...)` 的参数中加入小吴，再让输出同时带上剩余数。验收：小林 3、小陈 2、小吴 1 各占一行，小周不出现。现在已经能读懂方法调用和对象集合，再去 [[20-后端/Java/04-从TypeScript到Java-编译与运行|第 04 节]]，看一个用户查询怎样从源码变成可运行的产物。
