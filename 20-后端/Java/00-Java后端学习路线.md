# Java 后端学习路线

**从 [[20-后端/Java/01-变量类型与输出|第 01 节：变量、类型与输出]] 开始。** Java 是接下来做后端开发的主力语言。第一目标是独立交付一个业务模块，包括澄清规则、设计接口、实现、测试、部署和排障。第二目标是能解释系统在并发、重试、依赖故障时会发生什么，并用实验验证。后续每节按 [[20-后端/Java/AGENTS|课程编写要求]] 展开。

## 岗位要求怎样转成学习目标

2026-11-19 调研的样本来自中国大陆公开职位。以下区分了各岗位侧重，适合用来选择学习深度。

- **入门工程能力。** 亚马逊上海早期职业岗位接受 Java、TypeScript 等多种语言，关注编程实践、数据结构、算法与面向对象设计。已有前端工程经验可以迁移，Java 阶段重点补类型、集合、调试与独立实现。[岗位原文](https://www.amazon.jobs/en/jobs/10496564/software-development-engineer-early-career-2027-shanghai)
- **独立交付。** 博世苏州 Java 数据平台岗位要求能设计、实现、测试和交付模块，涉及关系型数据库、REST、Linux、Docker、代码评审、CI/CD 与排障。第 32 节按这个目标验收。[岗位原文](https://jobs.smartrecruiters.com/BoschGroup/744000146879028--java-xc)
- **复杂业务。** 腾讯云智三年以上电商 Java 岗同时关注交易建模、Spring、MySQL、Redis、消息队列、性能优化和生产问题定位。后半程围绕冲突、重试和补偿安排练习。[岗位原文](https://careers.tencent.com/jobdesc.html?postId=2098594908700061696)
- **平台方向。** 腾讯云存储专家岗强调大规模线上系统设计、主导交付与跨团队协作。课程用容量估算和故障分析建立基础，生产规模上的决策还需在真实工作中积累。[岗位原文](https://careers.tencent.com/jobdesc.html?postId=2056993391002169344)

## 起点、技术栈与贯穿项目

- 已有 Vue、TypeScript、Vite、Pinia、Axios、Electron 工程经验。用构建产物、类型契约、状态与异步调用理解 Java，同时单独练 JVM 和多线程。[[20-后端/00-后端学习导航|技术背景]]
- Express 与 Nest 已覆盖分层、依赖注入、运行时校验、统一异常和认证。后续重点观察 Spring 怎样选 Bean、绑定参数、管理事务和传递身份。[[20-后端/NestJS/00-NestJS学习路线-面向SpringBoot过渡|Nest 学习记录]]
- 项目管理 SQL 12 题已勾完，已有约 77 万条任务数据的索引实验。直接沿用表关系和执行计划，把练习时间留给映射、真实数据库测试和并发更新。[[20-后端/实践/数据库/02-MySQL项目管理系统SQL实战12题]] · [[20-后端/实践/Node后端学习项目/01-Node后端学习项目]]
- **学习栈**选 JDK 21 LTS、Maven Wrapper、Spring Boot 4.x、Spring MVC、MyBatis、MySQL。测试随课程引入 JUnit、MockMvc 和 Testcontainers。第 01 节只需要 JDK。[Java 版本说明](https://www.oracle.com/java/technologies/java-se-support-roadmap.html) · [Spring Boot 系统要求](https://docs.spring.io/spring-boot/system-requirements.html)
- **一条业务主线**是团队任务领取与变更记录。先用内存查用户，再逐步处理成员领取、单人成功、变更留痕、幂等重试及通知补发。用 HTTP 请求即可验收，熟悉的 Vue 页面可作为调用端。

## A　先写 Java，再学构建和测试（01～06）

第一次学，从 01 顺读，不必先看岗位调研，也不必先安装 Maven。01～02 只用 JDK：先算一个人的剩余量，再统计多个人。03 继续用 JDK，从成员对象展开构造方法、封装、继承、抽象类、接口和多态，并用列表管理对象。04 用已经写过的程序看清编译和运行；05 才把手动检查交给工具。表中有正文链接的是已写章节，后续主题是计划，不是已完成的学习记录。

**前五节的学习边界：**01 建立值、类型和变量位置的模型；02 学会控制流程和组织可复用计算；03 解释对象、类型关系和面向对象设计；04 解释源码怎样变成可运行的类；05 让构建和测试可重复执行。它们是连续的，不要把 04 的 classpath 错误当成业务代码错误，也不要把 05 的测试通过误认为整个系统已经完成集成验证。

**阶段产出**：一个能在终端独立构建、运行和测试的 Java 小模块。

## E　上线、观测与排障（25～32）

| 节次与主题 | 熟悉的入口 → 本节新增的机制 | 动手产出与验收 |
| --- | --- | --- |
| 25　Linux 与网络排障 | 从浏览器 Network 与 Node 端口追到 DNS、TCP、代理、进程和数据库 | 区分未监听、连接数据库失败、上游响应慢，各给一条能排除其他原因的证据 |
| 26　Docker 与部署 | 从 Vite/Electron 产物进入镜像、多阶段构建、Compose、网络、卷与健康检查 | 在干净环境启动服务，重建应用后仍能读到原数据 |
| 27　日志、指标与请求关联 | 从前端埋点、Axios 日志、ECharts 曲线进入请求 ID、错误率、延迟分位数与池指标 | 按 ID 查一次失败请求，针对 p95 上升提出两个可验证的原因 |
| 28　JVM 诊断 | 从 DevTools Performance/Memory 进入 JVM 堆、线程快照、GC 与 JFR | 区分 CPU 忙与线程等待，分别用一份诊断结果支持结论 |
| 29　压测与优化 | 把 SQL 索引对照实验扩展到整条请求链，处理预热、并发、吞吐与瓶颈 | 对一个慢接口提交基线、假设、修改和复测，说明测量条件 |
| 30　CI 与发布回退 | 从前端打包发布转到 Maven 验证、集成测试门禁及新旧代码与表结构的兼容 | 在 PR 中自动测试；演示一次应用回退，并说明迁移顺序 |
| 31　故障演练 | 从“页面一直转圈”沿请求 ID 追到慢 SQL、连接池或外部依赖 | 完成两次演练，记录时间线、影响、证据、恢复措施与回归测试 |
| 32　独立交付 | 结合前端调用方和服务维护者的视角，处理一项需求变更 | 交付“成员退出后不能再领取任务”的契约、实现、边界用例、部署说明和评审记录 |

**主线验收**：另一人能启动服务、调用接口、运行测试。能现场解释一次并发冲突、一次事务回滚和一次慢请求，展示每个判断所依据的证据。
