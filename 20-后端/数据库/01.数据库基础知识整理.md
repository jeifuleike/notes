# 数据库基础知识整理

## 一、数据库是什么

数据库（Database）是用于：

-   存储数据
-   管理数据
-   查询数据
-   修改数据

的软件系统。

简单理解：

    应用程序
        |
        ↓
    数据库
        |
        ↓
    保存的数据

例如：

用户注册：

    用户输入账号密码

            ↓

    后端服务

            ↓

    MySQL保存用户数据

------------------------------------------------------------------------

# 二、关系型数据库

MySQL 属于：

> 关系型数据库（Relational Database）

核心思想：

使用：

    表（Table）

保存数据。

例如：

用户表：

  id   username   email
  ---- ---------- -------------
  1    Tom        tom@qq.com
  2    Jack       jack@qq.com

这里：

-   一张表代表一种数据
-   一行代表一条记录
-   一列代表一个属性

------------------------------------------------------------------------

# 三、数据库中的基本概念

## 1. Database

数据库。

例如：

    project_system

一个数据库可以包含很多表。

------------------------------------------------------------------------

## 2. Table

表。

例如：

    users

    projects

    tasks

------------------------------------------------------------------------

## 3. Row

行，也叫记录。

例如：

    id=1
    username=Tom
    email=tom@qq.com

代表一个用户。

------------------------------------------------------------------------

## 4. Column

列，也叫字段。

例如：

    username
    email
    created_at

表示数据属性。

------------------------------------------------------------------------

# 四、SQL是什么

SQL：

Structured Query Language

结构化查询语言。

用于操作数据库。

主要分为：

## 查询

SELECT

例如：

``` sql
SELECT *
FROM users;
```

## 插入

INSERT

例如：

``` sql
INSERT INTO users(username)
VALUES('Tom');
```

## 修改

UPDATE

例如：

``` sql
UPDATE users
SET username='Jack'
WHERE id=1;
```

## 删除

DELETE

例如：

``` sql
DELETE FROM users
WHERE id=1;
```

------------------------------------------------------------------------

# 五、表设计基础

设计数据库时，需要考虑：

-   数据如何保存
-   表之间如何关联
-   如何避免重复数据

例如：

一个项目管理系统：

    users

    projects

    tasks

关系：

    用户
     |
     | 创建
     ↓

    项目
     |
     | 包含
     ↓

    任务

------------------------------------------------------------------------

# 六、主键 Primary Key

主键：

> 唯一标识一条数据。

例如：

users：

  id   username
  ---- ----------
  1    Tom
  2    Jack

id就是主键。

特点：

-   唯一
-   不为空
-   通常不会改变

常见设计：

``` sql
id BIGINT PRIMARY KEY AUTO_INCREMENT
```

------------------------------------------------------------------------

# 七、外键 Foreign Key

外键用于表示表之间关系。

例如：

projects：

    id
    name
    owner_id

其中：

    owner_id

指向：

    users.id

关系：

    users

    id=1 Tom


    projects

    owner_id=1

表示：

Tom 创建了这个项目。

------------------------------------------------------------------------

# 九、NULL是什么

NULL 表示：

> 没有值。

例如：

用户没有填写手机号：

    phone=NULL

注意：

NULL 不等于：

    0

    空字符串 ''

它代表未知或不存在。

------------------------------------------------------------------------

# 十、数据库约束

约束用于保证数据正确。

## NOT NULL

不能为空。

例如：

``` sql
username VARCHAR(50) NOT NULL
```

## UNIQUE

唯一。

例如：

``` sql
email UNIQUE
```

不能出现两个相同邮箱。

## PRIMARY KEY

主键。

保证：

-   唯一
-   非空

## FOREIGN KEY

保证关联关系。

------------------------------------------------------------------------

# 十一、表关系

## 一对一

一个用户：

    一个账号
    对应一个资料

例如：

    users

    user_profiles

------------------------------------------------------------------------

## 一对多

最常见。

例如：

    一个用户

    拥有多个项目

    users

    1

    |

    N

    projects

------------------------------------------------------------------------

## 多对多

例如：

    一个项目

    多个成员


    一个成员

    多个项目

需要中间表：

    project_members

    project_id
    user_id

------------------------------------------------------------------------

# 十二、数据库查询流程基础理解

简单查询：

``` sql
SELECT *
FROM users
WHERE id=1;
```

数据库大概流程：

    接收SQL

    ↓

    解析SQL

    ↓

    选择执行方式

    ↓

    访问数据

    ↓

    返回结果

后面学习索引后，会进一步理解：

    查询
     ↓
    索引
     ↓
    B+ Tree
     ↓
    定位数据

------------------------------------------------------------------------

# 十三、为什么需要数据库设计

错误设计：

    users

    username
    project1
    project2
    project3

问题：

-   数据重复
-   难以扩展
-   查询困难

更合理：

    users

    projects

    project_members

通过关系表达数据。

------------------------------------------------------------------------

    亿级

-   缓存
-   分库分表
-   数据一致性

# 总结

数据库基础核心：

1.  数据库负责保存和管理数据
2.  表保存一类数据
3.  行代表一条记录
4.  列代表属性
5.  SQL负责操作数据
6.  主键唯一标识数据
7.  外键连接不同表
8.  表设计决定系统扩展能力
9.  数据量增长后需要索引和优化

数据库学习不是背 SQL，而是理解：

> 数据如何组织、如何关联、如何被高效查询，以及如何保证正确。
