# 前端 TypeScript 编码与文件规范

适用于运行在浏览器中的 TypeScript，包括组件应用和原生 TS。框架入口、组件扩展名、Hook 命名及样式系统沿用目标仓库。下面的文件名可作为团队尚无约定时的起点。

## 文件放哪里、怎么命名

按用户能完成的业务操作组织模块。页面入口协调布局、子模块和共享状态。父模块使用子模块的公开入口，模块内部仍可按职责直接导入。公开入口可以是现有页面、组件或函数，无需为每层目录增加转发文件。

| 内容 | 推荐归属 |
| --- | --- |
| 单一使用点的类型、常量或小函数 | 留在使用处，优先保持能在一处读懂 |
| 多处使用的展示类型、筛选条件 | 就近放在业务模块的 `types.ts` |
| 模块共享的固定选项或映射 | 放在 `constants.ts`，用户输入和请求结果归状态所有者 |
| 接口请求与响应类型 | 跟随服务定义，页面导入契约后派生所需展示类型 |
| 接口结果到视图数据的转换 | 有适配需求时放在 `transformers.ts`；普通纯函数按业务动作命名 |
| 组件状态、订阅和资源清理 | 跟随拥有生命周期的组件或模块；提取后使用能说明行为的名称 |
| 测试 | 沿用仓库约定；新项目可将单测与被测文件同目录，例如 `transformers.test.ts`，浏览器测试按用户流程命名 |

一个文件足以表达职责时直接建文件；同类实现多到需要分别维护时再建目录。名称应帮助检索，如 `groupOrdersByStatus.ts`，避免把格式化、请求、弹窗逻辑全收进 `helpers.ts`。新项目可约定业务目录用短横线（`order-list/`），类型用 PascalCase（`OrderRow`），函数和变量用 camelCase（`groupOrders`、`selectedOrderId`）。已有仓库沿用其大小写与连接符。

**订单列表例子。** 单页私用的行类型留在列表里。列表与导出视图共用它时再提取 `OrderRow`。服务端的 `OrderResponse` 仍归订单服务。若响应已能直接展示，直接使用原类型和数据即可。

## 代码和类型怎么写

- 读清请求参数、返回值、字段可空性、单位和失败语义。遇到未知的外部输入，用 `unknown` 配合已有校验收窄；契约无法核实时，记录缺口并暂停依赖这些字段的部分。类型断言和 `any` 不能证明数据符合契约。
- 用具名类型表达跨文件契约，临时值优先让编译器推断。用说明业务含义的变量名，注释解释约束产生的原因。格式交给仓库的 lint 和 formatter。
- 分支、循环使用完整代码块。简单无返回值的提前退出可沿用团队写法。三元表达式只表达简单两项取值，多步骤逻辑写成顺序语句或具名分支。
- 转换函数只处理数据，保留 ID、单位、精度以及空值语义。请求、状态提交和消息反馈留在对应调用处。例如以下函数假设输入单位为件，`0` 显示为零，缺值显示为占位符。

```ts
function formatQuantity(quantity: number | null): string {
  return quantity === null ? '—' : String(quantity)
}
```

## 状态、副作用与复用

- 由实际需要共享数据的最小范围持有状态。可取消的表单编辑保留独立草稿，提交成功才更新已保存值，失败保留草稿。公共展示组件通过参数和事件接入业务。
- 点击保存、删除或跳转时，从对应事件直接发起。筛选变更、手动刷新和轮询确实读同一资源时，让它们共享查询入口，并分别考虑加载提示。
- 针对具体竞争选择处理方式。用户依次搜索 A、B，A 最晚返回时只能展示 B 的结果；保护数据回写，也要防止 A 提前清掉 B 的加载态。保存按钮的重复提交则应在提交入口防重入。离开页面时释放监听、定时器和订阅。
- 空数据、加载中、失败分别表示。确认请求层的失败契约由返回值还是异常表达。默认提示已覆盖错误时，由调用方停止后续成功操作；需要保留输入或局部重试时，由对应模块负责。
- 先查已有组件、服务和工具。多处实现具有同样的数据语义、交互和生命周期时再抽取。迁移调用方时检查默认值、精度、错误反馈、键盘交互和资源释放。

## 提交前自查

从一个真实用户入口验证正常路径和受改动影响的边界。数量字段查零与空；表单查失败后输入仍在；连续搜索查慢响应晚返回；公共能力变更查全部调用方。按项目提供的命令执行相应检查。
