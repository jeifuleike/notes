# NestJS 巩固：精简项目任务管理 API

## 1. 位置与目标

接续 [[00-NestJS学习路线-面向SpringBoot过渡]] 的基础7节，本计划对应**第08～12节，共5节**，通常一天一节。利用熟悉的数据库业务，独立组织一个小Nest应用；完成后转Java / Spring Boot，不扩展成大型项目。

本篇维护学习范围与验收目标。代码、接口契约、章节TODO、启动命令和实际验收记录，待开始实践时统一放入 [node-backend-study](../../../../node/node-backend-study) 的独立项目目录，不在笔记中复制第二份运行手册。**当前是计划，项目代码尚未创建。**

建议每节1～2小时；数据迁移或权限实现超时时顺延，不为了“当天完成”跳过失败路径。

## 2. 项目范围

项目：用户登录后创建项目，在有成员资格的项目下管理任务。

- 业务模块：Users、Auth、Projects、Tasks；数据库模块提供共享连接池。
- 技术：NestJS、TypeScript、MySQL、mysql2、JWT；HTTP请求文件作为主要操作入口。
- 数据：users、projects、project_members、tasks。复用已有设计与迁移思路，先核对字段兼容性；新增迁移，不改写历史迁移或清空旧学习数据。
- 身份：只信任经过验证的token；客户端不得指定项目owner或任务creator来冒充别人。
- 权限：项目成员可查看项目、创建/查询任务；项目owner或任务creator可修改任务状态。非成员不能访问。
- 成员准备：通过本地学习种子准备owner、普通成员、非成员；本轮不做公开邀请或成员管理接口。

只实现注册、登录、当前用户，创建/查询项目，创建/查询任务和修改任务状态。暂不加入项目删除、文件上传、消息通知、复杂角色系统、刷新token、缓存、消息队列和完整前端页面。

## 3. 第08节：确定范围并搭好项目

- **重点**：从独立应用重新组织模块，不直接复制基础工程全部文件。
- **动手**：列出上述功能对应的模块与依赖；建立空模块、配置和数据库Provider，核对四张表及迁移，准备独立学习数据。
- [ ] **验收**：工程启动、数据库连接正常；能解释每个模块负责什么。明确哪些是本轮接口，哪些暂不做。

不重复写一篇数据库原理，直接关联 [[20-后端/数据库/02-SQL基础与数据库设计]]、[[20-后端/数据库/56-Migration数据库迁移]]。

## 4. 第09节：完成用户与认证闭环

- **重点**：把基础课的DTO、Repository、Service和Guard用于完整注册登录流程。
- **动手**：实现注册、登录、当前用户；复用已有密码派生与JWT知识，自己完成Nest中的依赖接线。
- [ ] **验收**：注册不保存明文，重复邮箱409，错误密码401，合法token可读取当前用户；无效或过期token401。用户信息响应不包含密码或哈希，访问token只按约定在登录成功响应中返回，不写入日志。

参考：[Nest Authentication](https://docs.nestjs.com/security/authentication)。通用原理复用 [[20-后端/认证与安全/01-登录认证与Cookie-JWT-Session重点总结]]，不重写算法教程。

## 5. 第10节：完成项目与成员权限

- **重点**：在Service中落实事务和业务权限，区分“已登录”和“属于该项目”。
- **动手**：当前用户创建项目并自动成为owner，事务同时写入两张表；实现按ID查询项目，检查真实成员关系。
- [ ] **验收**：第二步写入失败时项目不残留；owner与普通成员可查询，非成员403，项目不存在404；ownerId来自认证身份。

使用A、B、C三个学习账号分别作为owner、成员、非成员，不靠固定用户ID或客户端传角色放行。

## 6. 第11节：完成任务业务

- **重点**：复用已有分层，独立实现一组有权限约束的任务接口。
- **动手**：成员创建任务、查询所属项目任务、修改任务状态；创建者取当前身份。列表先固定合理上限和稳定顺序，可做简单状态筛选，不扩展复杂分页。
- [ ] **验收**：非成员不能创建或读取；普通成员不能修改别人的任务，creator或owner可修改；非法状态400，目标不存在404。通过其他项目的路径或ID不能绕过权限、访问错项目的任务。

权限规则检查请求身份、真实成员关系和任务归属，不只是验证token。不存在记录与无权限的响应顺序按项目约定保持一致。

## 7. 第12节：验收、测试与复盘

- **重点**：验证完整业务与失败路径，确认自己能维护这套代码。
- **动手**：按“注册 → 登录 → 创建项目 → 创建任务 → 查询/更新”的流程跑通请求文件；验证三个身份的权限边界、重复数据和事务回滚。
- **测试**：补少量有价值的自动化用例，例如非成员被拒绝、任务creator与普通成员的修改差异；Repository用替身隔离。真实事务回滚通过学习数据库验收，不能用替身测试声称数据库已经验证。
- [ ] **验收**：运行说明、配置示例、迁移与请求样例齐全；记录实际通过/失败结果；能解释DI、校验、认证、权限与事务，并列出迁移到Spring Boot时需要替换的框架部分。

参考：[Nest Testing](https://docs.nestjs.com/fundamentals/testing)。只补必要测试，不为追求覆盖率把项目拖成测试框架专项。

## 8. 完成后的去向

完成第12节后，先学Java必要基础，再用Spring Boot重写同一套核心业务和接口。保留表结构与权限用例作为对照，集中比较构造函数注入、参数绑定、校验、事务和安全链路。

若想接页面，可以用熟悉的Vue做最小操作界面，作为自愿加餐；它不影响本轮完成标准和转Java的时机。
