## 工作方式

- 默认先给方案，不直接修改文件或执行有副作用的操作。
- 只有用户明确要求“修改 / 修复 / 添加 / 删除 / 执行 / 开始做”，或明确确认上一轮方案（如“行 / 可以 / 按这个做”），才动手。
- 询问“怎么做 / 能不能 / 是否 / 为什么 / 看看 / 评估”等，只分析并给方案，不擅自改代码或配置。

## 知识沉淀

- 完成实质性任务后，只有结论满足“普适 + 可复用”才提议沉淀：优先通用知识（原理、方法、架构模式、决策框架、边界）或提效资产（流程、脚本、模板、检查清单）；单次小修复、偶发环境问题、一次性命令不提议。
- 提议时必须说明：要存什么（标题 + 最多 3 条要点）、为什么值得存（未来什么场景会用）、去向 `00-Inbox`，然后问一次是否记录。
- 沉淀一律先写入 `00-Inbox/`，不要写正式库；不要询问是否发布，整理时统一处理。
- 用户没有确认时不要重复追问；同一话题一次会话最多问两次。
- 只写入本机配置的知识库；公司内容不得写入个人知识库。
- 用户说“记一下 / 沉淀 / 保存 / 以后有用 / 复盘这次对话”时，调用 `kb-curator`。
- 纯问答、简单查询、一次性命令输出，不提议沉淀。
- 归档去向：人读知识按 `config.json` 的领域路由；AI 工作流规范、工程约束、决策、项目上下文进 `70-AI知识资产/`；收藏或评估的第三方 Skill 进 `80-Skill库/`；Codex 自定义 Skill 的备份统一放 `80-Skill库/Codex备份/skills/`，运行副本在 `~/.codex/skills/`。
- 备份、比较或恢复 Codex Skill/提示词时，调用 `codex-asset-sync`；`notes` 只作备份，Codex 运行时读取 `~/.codex` 的真实副本，不使用 junction。
- 需要回忆旧知识时调用 `kb-query`，它只读，回答给出 `路径:行号`。
